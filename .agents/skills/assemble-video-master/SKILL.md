## Shared-code preflight

Before creating or copying any episode-local script, read `leverage-video/src/shared/reuse-registry/registry.json`, inspect every registered shared module, and run `node leverage-video/src/shared/reuse-registry/create-reuse-decision.mjs <episode-workspace>`. The command fails if any episode-local script already exists; do not create a retroactive audit. In the generated `<episode-workspace>/schema/shared-reuse-decision-v1.json`, record exactly one `reuse`, `extend_shared`, or `not_applicable` decision with a concrete reason for every module. Run `node leverage-video/src/shared/reuse-registry/validate-reuse-decision.mjs <episode-workspace>/schema/shared-reuse-decision-v1.json --phase pre-script` and stop unless it passes. This binds the audit to the current registry, current module bytes, active episode, and empty pre-script inventory.

Reuse shared code when it already satisfies the contract. When reusable behavior is missing, add and test the minimum general implementation under `leverage-video/src/shared`, register it, rerun the complete reuse audit, and then consume it from the episode. Episode-local code may bind composition IDs, paths, locked assets, and episode configuration; it must not copy, fork, or reimplement shared behavior, validators, renderers, file-integrity logic, transition logic, media QA, or delivery locking.

After episode bindings exist, record each `reuse` or `extend_shared` consumer source path, checksum, and real shared import marker. Run the validator again with `--phase consumption` before any Remotion still, Studio, preview, render, or composition lock. Run the relevant shared and episode tests separately; do not encode a self-reported test result as trust evidence. A structurally complete pre-script decision without verified source consumption is not render authorization. The shared assembly-plan builder must read this exact decision file, verify its checksum, and rerun consumption validation; plan input may not self-report `result: pass`.

For an episode whose non-empty script directory demonstrably predates this gate, stop unless the user gives explicit user authorization for a one-time migration of that exact episode. Then run `create-legacy-reuse-decision.mjs`, record the full existing script inventory and checksums plus the exact authorization message/time, and require `--phase legacy-migration`. Do not move or clear the script directory, do not fabricate an empty `pre_script_inventory`, and do not describe the migration as a pre-script audit. Preserve every baseline script byte; list only newly added binding files in `legacy_additions`, attach their current checksums and real shared imports, and require `--phase consumption` before rendering. Any baseline mutation or undeclared addition is a blocker.

## Preconditions

- The exact script, validated narration master, audio-timed storyboard, and active asset manifest are locked.
- Immediately before assembly, rerun `validate_visual_approval_state.py validate-locked` against the active episode state and repository root; require a passing `visual-assets-lock-verification-v1` whose current disk checksum map equals the locked visual manifest.
- The active `per-shot-visual-direction-review-v3` evidence is approved and bound to storyboard/manifest, including machine scene class, white-cat, active route, visual language, and route-resolved final visible-text fields. `comic-imagegen` and `doodle-slides` are forbidden in new, modified, revoice, preview, Studio, composition-lock, and render work; unchanged completed legacy evidence remains readable only. White-cat `imagegen` and every `xuan-paper-diorama` shot must be text-free and title-free. 宣纸与墨线知识卡 assets must match their route-catalog-pinned Skill/profile fingerprints. Other active routes retain their own text contracts. Missing, pending, incompatible, stale, or mismatched evidence blocks.
- Require `visual_direction_artifact_policy`: current work is `current_v3`; v1/v2 may enter only as unchanged completed `legacy_read_only` evidence with no modified shot IDs. A reopened legacy shot must supply v3 before still, preview, Studio, composition lock, or render.
- Every non-Whiteboard character family has a passing `action-state-schedule-v2`: formula-correct state count, at most five states, complete frame coverage, 18–75-frame multi-state occurrence spans, at least 15 clean frames after each incoming 18-frame reveal, and exactly `N - 1` shared 0.6-second watercolor transitions. Whiteboard retains its explicit exemption.
- Every active visual and normalized opening cover have measured per-file 1920×1080 evidence, and every still, preview, contact sheet, and render target uses the native `16:9`, `1920×1080` landscape canvas.
- Every data scene, transition asset, and shared opening-cover archive/normalized raster has passed its own QA.
- Every ordinary boundary has a structured `scene-transition-v3` decision with valid semantic class, source/next routes, recomputed route-first or shared-fallback recommendation authority/rule ID, selected registered kind/options, renderer, and approval hash. `cut` requires zero seconds/frames and empty options; visible effects require 0.3–0.6 seconds. Missing, `none`, wrong renderer, or unresolved evidence blocks.
- The exact shared cover has a checksum-matching archived episode copy and deterministic normalized raster, and the exact first-sentence timing evidence has passed QA under `cover-only-v1`.
- The active episode has either a passing pre-script `shared-reuse-decision-v1.json`, or a passing explicitly authorized one-time legacy migration with a complete baseline inventory and unchanged baseline bytes.

For `revoice_variant`, the standard active-manifest narration fingerprint may remain bound to the parent. Require instead the immutable parent visual manifest plus a passing `revoice-visual-binding` that records the approved retiming-only storyboard, replacement narration master, exact locked visual sequence, prior per-image approvals, unchanged approved white-cat/route map, and unchanged canvas/cover/opening evidence.

## Assemble a revoice variant

- Consume the replacement narration master and approved retiming-only storyboard as timing authority while loading visual assets only from the parent manifest and `revoice-visual-binding`.
- Preserve the locked visual sequence and parent direction/transition evidence. A parent using retired `comic-imagegen` cannot enter revoice. Revoice never recomputes state count/order or any inter-shot transition kind/options/duration/frame count; redistribute only shot/boundary placement and allowed internal timing fields. Block when a derivative transition differs from its parent, a shot is shorter than its locked transition, or a locked multi-state occurrence leaves the 18–75-frame span or has fewer than 15 clean frames after reveal.
- Recompute the cover hold from the replacement first-sentence end frame and bind all later shots, existing state occurrences, and sound-effect cues to the new real-audio schedule while preserving each transition length exactly.
- Do not invoke image generation, change an image, rewrite the parent visual manifest, or reuse the old encoded master with an audio swap. Build and QA a new source-derived composition, per-topic opening, contact sheet, and final master.
- Preserve the parent BGM mode. Disabled remains free of BGM access. Enabled reuses only the already archived checksum-matching source and the same mix policy after the new duration lock.

## Assemble the BGM-free base

1. Apply `cover-only-v1`: build one reusable `EpisodeOpening` component from the single archived cover raster normalized deterministically to 1920×1080. Start both the cover and validated narration master at composition frame 0, use no added text layer, and end the opening component at the first sentence's real end frame.
2. Bind every later shot directly to its exact narration-master in/out time with no opening-frame offset, plus its accepted asset/state family, state schedule, crop, transition, approved route-owned on-screen-text intent, and sound-effect cues. Do not accept a generic top-title or timeline text-overlay field.
   - Reuse `leverage-video/src/shared/scene-transitions`; every outgoing non-terminal shot must execute its exact user-selected registered kind and options without fallback, normalization, or substitution and without changing locked shot/audio frames or total duration.
   - Preserve only `OPEN-00 → S01` as the zero-overlap hard-cut exception. Only the final clean hold may omit an outgoing transition.
3. Enforce `action-state-schedule-v2` and `intra-shot-watercolor-bloom-v1`. One-image shots have zero intra-shot transitions. Whiteboard consumes one approved silent MP4 and remains wrapped by the approved semantic inter-shot decision.
4. Keep paired exact `source_text`, punctuation-free `display_text`, and narration-derived cue timing locked. Do not mount a caption component in the caption-neutral base. For every active visual whose manifest records `visual_generation_route: ian-handdrawn-ppt`, preserve the approved raster and its baked-in labels exactly and apply `ian-full-frame-mask-sweep-v1` from the Remotion reference; do not recreate labels in Remotion.
5. Under `explicit-visual-generation-route-v3`, route `imagegen` and `xuan-paper-diorama` to `NarrativeScene`, Ian and `ink-doodle-knowledge-card` to `GraphicScene`, and Whiteboard to `WhiteboardScene`; reject `comic-imagegen` and `doodle-slides`. 宣纸与墨线知识卡 scenes consume only exact-byte-approved 1920×1080 PNGs with prompt/reference and pinned-style provenance; Remotion must not simulate either style. Only Ian may use `ian-full-frame-mask-sweep-v1`; Ink Doodle holds or watercolors between approved states. `TransitionedScene` creates no tail for `cut` and requires exact zero-overlap adjacency; visible effects retain their approved tail. Terminal clean hold has no outgoing transition.
6. Assemble narration, accepted visuals, state families, raster data/logic visuals, transitions, approved route-owned raster/annotation text, and only sound effects listed with passing QA in the active sound-effect manifest. Add, rewrite, reposition, or remove no title/text overlay; add no opening-source audio, subtitle stream, unlisted sound effect, BGM, or arbitrary tail padding.

## Preflight and lock duration

- Build through `leverage-video/src/shared/assembly-plan`, which validates the visual-direction review, white-cat compatibility, explicit shot routes, exact asset-route equality, and shared reuse evidence. Before any Remotion still, Studio, preview, render, or composition lock, run `node .agents/skills/assemble-video-master/scripts/validate-scene-transitions.mjs <assembly-plan.json> <composition-source.tsx>`. Stop on any missing, pending, unsupported, substituted, out-of-range, unbound, or unconsumed direction/route/transition evidence. Legacy v1 plans are historical evidence only; migrate the active storyboard and plan through the required reviews before new render work.
- Resolve an existing supported Chrome-family executable and pass its absolute path explicitly to every Remotion still, Studio, and render command.
- Never run a bare command that could download Chrome Headless Shell.
- Validate one still and visually inspect it before any full render.
- Inspect the cover opening start/middle/end, `OPEN-00 → S01` hard-cut boundary, complete first-sentence cover hold, first-sentence A/V sync from frame 0, every later action state and boundary, every ordinary transition's first/middle/final frame, every scene's representative frames, every data reveal, approved on-screen text, framing, registration, flicker, unintended black frames, hold timing, and the reserved bottom-caption safe area.
- Repair failures and repeat until the BGM-free base passes; then record `composition_lock` with the BGM-free input fingerprint/checksum, exact duration, QA result, and lock time.

## Require the final caption choice

- After `composition_lock` and before any final master or per-topic opening render, set phase `awaiting_caption_delivery_choice`, present exactly `1. 无字幕；2. 有字幕；3. 有字幕跟无字幕的视频都有`, and stop for an explicit selection.
- Record `caption_delivery.mode` as `caption_free_only`, `captioned_only`, or `both`, with the user's exact message/time and mechanically derived `required_delivery_roles` plus `required_internal_qa_roles`.
- Render captioned roles with exactly one versioned caption component using only the locked punctuation-free `display_text` and narration-master cue timing. Render caption-free roles with that component absent.
- Keep zero subtitle streams and no subtitle sidecars in every mode. In `both`, all non-caption inputs, frame schedules, audio, BGM mode, visual order, and opening sources must be identical; only the caption layer may differ.

## Resolve audio mode, render, verify, and deliver

- Set `bgm.mode` to `disabled` when it is missing or unspecified. In this default mode, do not read the shared BGM selector, inspect or copy any BGM file, create a BGM track, or ask the user whether to enable it. Render with narration and only manifest-listed, QA-passing discrete sound effects.
- Use `enabled` only when the active episode state records complete current-episode enablement and composition-lock evidence. If either is missing or inconsistent, stop before any BGM access. Then follow the final-mix reference to resolve and validate the selected BGM and mix it as a separate narration-subordinate track.
- Render only the full masters in `required_delivery_roles` and their matching openings in `required_internal_qa_roles`, each as a 1920×1080, 16:9 landscape, 30 fps H.264 MP4 for Douyin and Bilibili validation. Each required master has one same-caption-role per-topic opening rendered from the same `EpisodeOpening` component and exact inputs used at frame zero; do not render an independent approximation or embed a previously compressed opening render into the master. The full master already contains that opening; keep the standalone opening only as internal prefix-QA evidence.
- Decode and measure every generated still and contact-sheet raster; probe and fully decode every selected preview and final file. Verify exact dimensions, codecs, duration, A/V sync, black frames, representative playback, cover QA, role-appropriate contact-sheet evidence, zero subtitle streams, and role-appropriate burned-in-caption presence or absence. Verify that every included sound effect matches the active sound-effect manifest with no unlisted effect. In disabled mode, verify provenance shows no BGM input or track; in enabled mode, verify BGM coverage, narration dominance, and the recorded mix input fingerprints.
- Create an active delivery transaction manifest under the episode workspace's `schema/`, then copy only QA-approved full masters in `required_delivery_roles` to the fixed delivery directory with distinct new versioned filenames. Never copy an opening role or include it in that manifest. Compare sizes and checksums, probe and decode every delivered copy, and require the transaction manifest's role set to match `required_delivery_roles` exactly. Never use the shared directory's full listing as the role set or delete unrelated/historical deliveries. Return links to the selected complete full video or videos, the cover, narration master, and contact-sheet evidence; do not return the standalone opening.
- For a revoice variant, include the `variant_id` and caption role in every new filename, return the replacement narration master, require a fresh caption choice, and leave every parent render and delivery unchanged.

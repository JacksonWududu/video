# Run Knowledge Video

Treat the production as one resumable workflow, not as unrelated tasks.

For the explicitly selected `illustrated-flipbook` style, read [illustrated-flipbook-v1.md](references/illustrated-flipbook-v1.md). It defines the conditional static-spread/body-text/browser branch while retaining the existing workflow gates. Present 图文翻书 alongside the existing choices in the post-cover style form.

For a concise Chinese overview or workflow-maintenance map, read [references/whole-workflow-summary.md](references/whole-workflow-summary.md). Treat the state-machine reference as the authoritative execution contract. Read [references/visual-language-and-comic-routing.md](references/visual-language-and-comic-routing.md) whenever constructing, producing, assembling, or retiming a v2/v3 visual contract. For a completed-episode voice-only derivative, also read [references/revoice-variant.md](references/revoice-variant.md) completely.

## Start or resume

1. Read [references/workflow-state-machine.md](references/workflow-state-machine.md) completely before taking workflow action.
2. Classify the request as a new video or a resume before writing anything. A completed-episode voice-only derivative is `resume` with `resume_mode: revoice_variant`. For every new video, create exactly one fresh episode workspace under `leverage-video/src` directly from the workspace contract in the state-machine reference; never inspect, copy, or use an existing episode workspace as a template. For every resume, reuse only the workspace identified by its state manifest; never create or clone a replacement workspace.
3. Enforce the episode workspace contract in the state-machine reference. Pass the resolved workspace path to every node Skill and keep every generated artifact in its assigned directory; do not invent convenience folders.
4. Locate the episode manifests and reconstruct the latest valid phase from artifact paths, hashes, QA status, and input fingerprints; never infer completion from filenames alone.
5. For a new video with no episode state, route a user-supplied topic directly to Gate 1 validation or resolve dated local topic options through `$discover-video-topics`. For a resume, reconstruct the recorded topic and phase; never rerun topic discovery merely because state exists. In `revoice_variant`, keep the parent topic and gates locked.
6. When the local narration source used by a completed episode is later revised and the user wants a video with the new wording, classify that request as `new_video`, create a fresh episode workspace, and rerun every Gate and production phase from the current local source. Keep the completed episode and all its artifacts unchanged. A history strikethrough remains informational and does not prevent selecting the same topic again.
7. Preserve every gate in `manual`. Immediately after Gate 2, ask exactly `1. 叙事白猫；2. 固定白猫` and stop until the user explicitly selects `narrative_adaptive` or `fixed_centered_reference`; never default or infer the choice. Then invoke `$imagegen-calligraphy-cover` in pre-style `open_unconstrained` mode and independently generate 16:9, 9:16, and 4:3 publishing covers. Perform the user's delegated structured QA, show passing results without asking for cover approval, and never claim user approval. Only after the cover package is current, ask one combined post-cover form for episode style, conditional cover-style scope, `standard | rich` density, `manual | one_click` approval mode, and `colocated_voice | edge_tts` narration source; stop once. Build and validate the existing hash chain in memory with `post-cover-selection-batch-v1`, then write all applicable records and gates to `episode-state.json` once and move directly to `audio_validation`. A missing, ambiguous, stale, or invalid field causes zero partial state writes. Never default or choose per shot. Bind the selected immutable episode-local style snapshot and cohesion profile into every current v3 direction row and generation QA. `one_click` still stops for the complete visible-text map, final exact visual hash-list, and caption choice. Unchanged episodes already using the former per-choice phases remain legacy-compatible without migration. Revoice inherits the parent cover/style/cohesion/density/count/order/hashes and never regenerates or reselects them.

All project mechanical gates run first. If a gate fails, the user may explicitly name and release that current gate once under `one-time-explicit-user-mechanical-gate-override-v1` in [workflow-state-machine.md](references/workflow-state-machine.md). Preserve the failed result and bind the waiver to the exact episode, gate IDs, artifact hashes, and one source→target phase transition; atomically consume it on progression. Never infer a waiver from general continuation, reuse a consumed waiver, or extend it to later gates. This project rule does not override system safety, permissions, destructive-action approval, or external-service authorization.

Build the plan with the shared builder so it rechecks the exact decision file and checksum. After visual lock and before that reuse decision, require `$assemble-video-master` to build and validate automatic `knowledge-video-sound-design-v2` from the locked storyboard, action/Ian/Whiteboard/local-video events, and transition maps. Reuse the active shared SFX library first. When no hard-gate-compatible role exists, live-verify an official Mixkit item/license or Pixabay fallback, automatically download one cross-platform commercial/no-attribution source into a new immutable shared-library revision, and clean the exact temporary directory. Do not add a user review gate, use an approximate sound, mutate an old library manifest, or create an episode script before acquisition completes. Completed v1 designs remain read-only.

For a resumed episode whose scripts predate that gate, proceed only with explicit user authorization for one exact legacy migration. After adding only declared new bindings, require real shared consumer evidence and `--phase consumption`. Do not re-run a passing phase when its exact inputs and outputs still match. Re-run a phase and invalidate its downstream artifacts when an input fingerprint changes.

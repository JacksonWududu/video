# 知识视频完整工作流简表

## 文件定位

`$run-knowledge-video` 是端到端总编排 Skill，负责恢复状态、调用节点 Skill、控制 Gate、处理回滚并完成最终交付。

- 本文件：面向人阅读的中文流程摘要和维护地图。
- `workflow-state-machine.md`：阶段顺序、状态证据、Gate、阻断与回滚的执行依据。
- 各节点 Skill 的 `references/`：对应阶段的详细业务和制作规则。

## 当前流程

| 阶段 | 调用节点 Skill | 主要工作 | 阶段结果 |
|---|---|---|---|
| 0. 工程 workspace | `$run-knowledge-video` 编排器 | 先判断是新视频还是恢复任务；新视频按 `topic1` 的目录骨架创建唯一的新 `topic<N>`，恢复任务只复用状态清单唯一匹配的原目录 | 得到隔离、可恢复且目录合规的单集工程 |
| 1. 选题与 Gate 1 | `$discover-video-topics` | 从当天或最近一期本地选题文件读取候选，或者只校验用户直接提供的题目；检查范围、证据、安全和白猫视觉可行性；幂等记录已选历史 | 锁定一个选题及其来源信息 |
| 2. 定位现成口播稿 | `$run-knowledge-video` 编排器 | 按专业术语或主题关键词，在 `script-resource` 中确定唯一真实目录和唯一 `*_口播稿.txt`；拒绝软链接、缺失和歧义；保存同哈希版本化副本 | 得到可审计的口播候选稿 |
| 3. 口播审计与 Gate 2 | `$validate-video-narration` | 用英文权威资料核验事实、证据边界和平台风险；要求首句精确符合“苏格拉底的猫今天聊的是，主题”，以校验器机械提取非空主题文字；展示完整原稿；不静默改写；等待用户明确批准准确文本 | 锁定不可变的最终口播稿、首句和主题文字 |
| 4. 授权查找与验证音频 | `$validate-video-narration` | Gate 2 后询问是否可以查找音频；获准后只在已确定的主题目录顶层查找 `voice.mp3` 或唯一 `voice*.mp3`；归档、完整解码、转写对照并做可逆修复；从验证后的真实音频锁定首句结束帧 | 锁定唯一旁白主音轨、真实时长和首句结束帧 |
| 5. 音频定时分镜、逐镜视觉方向、逐边界转场与 Review | `$build-video-storyboard` | 七列分镜表显示每镜精确秒数；v3 逐镜同时锁定机器场景类、白猫、视觉语言、活动路线、路线解析后的可见文字，以及本地视频路线的绝对源路径；白猫 `imagegen` 固定无文字、无顶部标题；逐边界先取分镜生成路线专属建议，无匹配时才取共享 fallback，并锁定语义 `scene-transition-v3` | 锁定分镜、视觉方向、转场与校验和 |
| 6. 视觉素材生产 | `$produce-video-visuals` | 默认每四张普通素材审核；母图、角色参考、白板、用户 strict 和修订仍逐项严格审核；生成调用始终逐个 | 锁定逐项字节证据与批次清单 |
| 7. 合成、最终字幕交付选择与交付 | `$assemble-video-master` | v3 语义状态按真实音频定时；镜内默认直切、水彩仅显式选择；镜间连续语义 `cut` 不增加尾帧 | 按字幕选择交付完整视频 |

若已完成一期所用的本地口播原稿后来被修改，并要按新文字重新制作，应启动标准 `new_video`：新建 `topic<N>` workspace，重新执行 Gate 1、脚本解析与审计、Gate 2、音频验证、分镜、视觉审核和交付。已完成 episode 继续绑定其归档锁稿，不因脚本库后续修改而变化；同一题目在历史记录中的删除线仅作提示，仍可再次选择。文字变化不得走 `revoice_variant`。

## 已完成项目的换音色派生版本

当原 topic 已完成、用户只想换音色并复用原图片与画面顺序时，使用同一 episode workspace，以 `resume_mode: revoice_variant` 运行派生分支，不创建新 `topic<N>`：

1. 验证原锁定稿、原分镜、全部逐图批准、视觉清单及已交付成片的路径和校验和。
2. 用户明确指定并授权读取原主题目录顶层的一个 `voice*.mp3`。新音频必须逐字保持原锁定稿的口述内容与顺序；Skill 不调用 TTS。
3. 根据新音频的真实词句时间戳，把原分镜每一行的精确文本跨度重新对齐。禁止用新旧总时长比例整体缩放时间轴。
4. 锁定原镜头/素材/状态数量与顺序及字节、封面、视觉说明、构图、白猫、路线、结构、处理配置，以及父项目每个转场的 kind/options/duration/frame count/推荐来源/审批证据；只允许重算旁白、镜头和边界放置等明确许可的时间字段。任何转场参数或视觉合同变化退出纯重定时分支；包含 `comic-imagegen` 的历史父项目保持只读，不能进入 revoice。
5. 展示新的重定时七列 Summary 分镜（含精确三位小数秒数）和新旁白，重新完成 Storyboard Review。随后建立 `revoice-visual-binding`，证明继续使用的是原视觉清单、原逐图批准和锁定的路线映射；若包含本地视频，只按新目标帧重算播放速率，源字节不变；不调用 `$produce-video-visuals`，也不重复逐图审核。
6. 从原始视觉素材与新时间表重建公共合成并锁定时长，再为该派生版本重新执行最终字幕交付选择；不得继承父版本的选择，也不得只给旧编码成片换音轨。按选择重新渲染完整成片和内部片头 QA 文件，用同时带派生版本与字幕角色标识的新文件名只交付完整成片，保留所有原文件。

## 用户交互边界

共有五个强制内容审核节点：

1. **Gate 1：选题确认。** 用户选择本地候选，或直接提交自定义选题。
2. **Gate 2：口播稿确认。** 用户明确批准经过审计的准确文本。
3. **Per-Shot Visual Direction Review：逐镜视觉方向确认。** 转场前，用与分镜 Summary 相同的七列表单展示全部当前 active 行：`镜头｜时长（秒）｜画面｜白猫｜分镜生成方式｜可见文字｜锁稿原文`；时长、`OPEN-00` 和锁稿原文只读，生成镜头可改画面、白猫、分镜生成方式、可见文字。`local-video-file` 是永不默认的显式无猫路线，须逐镜填写绝对 `.mp4` 路径，不能批量套用；路线或路径改变都要刷新并重呈映射。支持全选、分批、整表和兼容性批量设置；表单只发送同时绑定映射与分镜哈希的 `visual-direction-form-submission-v3`，不直接写项目。画面修改会重开该镜，重建语义、分类、事实身份、白猫建议、结构/处理、路线/文字兼容性、构图、动作契约及相邻转场，再刷新哈希并重新呈现，不能直接视为批准。也可另行选择至少两个连续镜头发送 `storyboard-shot-merge-request-v1`：校验当前哈希后保留首镜、压缩后续编号，先重建语义/动作契约，再刷新受影响审核；`OPEN-00` 与 revoice 不可合并。兼容的非本地路线单改可直接选择；白猫、文字或本地视频路径变化仍按各自规则重算并重新呈现受影响镜头，保留其余批准证据。漫画审美仍可作为 `imagegen` treatment；`comic-imagegen` 已退出新建/修改选择。白猫只可走 `imagegen` 或 `xuan-paper-diorama` 并绑定规范参考。完整映射与哈希展示后方可批准；笼统授权不算选择。
4. **Per-Boundary Transition Review：逐边界转场确认。** 视觉方向全部批准后，最终分镜 QA 前，先按源镜头生图路线自身定义解析推荐；无匹配规则时才使用共享语义 fallback。必须展示推荐来源/规则、确切种类、必填参数、0.3–0.6 秒时长和理由。用户可以一次明确批准完整映射，也可逐条决定；未展示的默认、`你看着办`、`继续` 或笼统授权不算选择。任何最终选择仍须由共享 catalog、renderer 和测试支持，不能替换成近似效果。
5. **Storyboard Review：分镜脚本确认。** 视觉方向和转场映射全部批准并写入最终分镜后，必须展示含每镜精确秒数的完整七列分镜脚本和已验证旁白音频并暂停；它只批准当前 Markdown 校验和，不能代替逐镜视觉方向选择。只有用户明确批准当前分镜校验和后，才能生成或修改视觉资产。视觉生产先完成全部生成型/白板镜头；本地视频镜头留到最后，待其他素材全部批准后再逐镜解析、归档、按目标帧变速匹配并严格审核。若用户要求修改，修改后的新版本必须重新校验并再次 Review；视觉方向变化先重开受影响逐镜行，转场变化先重开受影响边界行。

Ian 知识视频镜头固定走 `ian-knowledge-video-frame-v1`：一项队列只产一张 1920×1080 PNG；禁用普通 PPT 页码、标题、副标题、自动标签和签名；无字模式不得出现文字，有字模式仅使用 v3 已批精确中文。联系表只作外层审核工件。

Gate 2 后的“是否可以开始寻找音频”是文件查找权限，不是内容审核 Gate。获准后自动推进到逐镜视觉方向确认；全部逐镜选择锁定后才推进逐边界转场确认，全部转场选择锁定后再推进 Storyboard Review。分镜版本获批并完成逐图审核后，自动推进到公共合成与时长锁定，然后必须停在最终字幕交付选择：`1. 无字幕；2. 有字幕；3. 有字幕跟无字幕的视频都有`，即仅无字幕、仅有字幕或两种都要。这也是输出模式选择，不是内容审核 Gate；未收到明确选择不得渲染。选择 1 或 2 都只交付 1 个完整视频，选择 3 交付 2 个完整视频。完整成片本身已经包含片头；独立片头只作为工作区内部 QA 文件，不复制到交付目录、不返回给用户，也不计入交付数量。换音色派生版本保留原 Gate 1/Gate 2、逐镜视觉方向和父项目 checksum-valid 转场映射及其全部参数，新时间表仍需一次新的 Storyboard Review，且每次派生渲染都重新选择字幕交付模式；旧父项目须先完成现有素材映射确认，原图批准只在视觉顺序锁、路线映射锁、转场锁和文件校验和全部不变时可继承。

标准旁白与 revoice 的用户原始音频统一存入 `assets/audio/user-source/` 的版本化文件；旁白母带及派生音频存于 `assets/audio/`。不得创建 episode 顶层 `audio/`。

## 工程目录约束

每个全新视频必须在 `leverage-video/src` 下创建一个全新的 `topic<N>` workspace；`N` 取现有 `topic数字` 的最大编号加一。`topic1` 只作为目录结构参考，不复制其中的文件，也不把新视频写回 `topic1`。恢复已有视频时，必须根据 `schema/episode-state.json` 唯一定位并复用原 workspace，不因失败或回滚另建目录。

该约束适用于本项目中任何 Skill 或普通对话发起的知识视频单集产物操作，不只适用于 `$run-knowledge-video`。单独调用节点 Skill 时，必须明确指定或唯一解析已有单集 workspace；零个或多个匹配都要停止询问，不能猜测或另建便利目录。Skill、`AGENTS.md`、共享 Remotion 基础设施、依赖、复用工具和仓库级文档属于工程维护文件，继续保存在各自所属位置。

```text
leverage-video/src/topic<N>/
├── assets/
│   ├── audio/       # 音频、旁白母版、BGM、音效
│   ├── image/       # 图片、封面、静帧、接触表
│   ├── narration/   # 字幕、口播稿、转写、分镜文本、TXT/SRT/VTT
│   └── video/       # 预览、中间成片、最终视频
├── script/          # JS/TS/TSX/MJS/PY 等程序代码
├── schema/          # 所有生成的 JSON、状态与素材清单
└── docs/            # 其余非代码文档、审计与制作记录
```

禁止为了方便在单集工程顶层新增 `work`、`output`、`temp`、`render`、`misc` 等目录。只有工具或明确的素材族确实需要时，才能在上述正确类别内建立用途明确的子目录，并把路径记录到 `schema/episode-state.json`。开始阶段工作前、每次阶段交接时以及声明完成前，都必须运行 `python3 .agents/skills/run-knowledge-video/scripts/validate_episode_workspace.py <episode-workspace>`；非零结果立即阻断，校验器不得自动移动或删除文件。

## 核心锁定规则

- 口播稿执行 `local-script-resource-only-v1`：必须来自 `script-resource` 中唯一定位的现成 `*_口播稿.txt`，来源字段固定为 `script_resource`；缺失时不接受聊天中粘贴的终稿绕过查找，也不自行生成或改写。
- 用户可自行修改已解析原稿；Codex 仅在用户明确要求修改该确切路径并取得所需文件权限后写入。聊天中粘贴的新稿仅是修改建议。未完成 episode 检测到源文件校验和变化时，保存新版本候选并回到 Gate 2，使旧审计、批准、锁稿、音频验证及全部下游依赖失效；已完成 episode 不受后续源文件变化影响。
- 未经明确许可不检查音频；只检查已解析主题目录顶层，不扫描相邻目录，不调用 TTS。
- 换音色派生版本只接受用户明确点名并授权的同主题目录顶层 `voice*.mp3`。口述文字变化会退出派生分支，须将新文字写入并唯一定位本地原稿后启动全新 `new_video`；视觉顺序、锁定白猫/路线映射或任何图片字节变化则退出派生分支，转入普通视觉修订流程。
- 通过验证的旁白主音轨是分镜、字幕、动作状态、转场和成片时长的唯一依据。
- 口播首句必须匹配“苏格拉底的猫今天聊的是，主题”，并继续机械保存其中的完整主题文字作为口播验证证据；该文字不再用于生成或修改片头封面。
- 每期按 `cover-only-v1` 只复用 `/Users/jackson/Desktop/video-edit/video-resource/cover.png`：Storyboard Review 前只读校验并锁定源哈希，批准后归档原字节，再通过等比 scale-to-cover 加最小居中裁切生成唯一 1920×1080 合成图；不叠字、不重绘、不拉伸、不补边、不进入逐图审批队列。从第 0 帧同时显示封面并启动旁白，封面持续到真实首句结束，随后仅 `OPEN-00 → S01` 允许零重叠硬切，后续镜头无片头偏移。完整成片和内部独立片头 QA 文件必须来自同一组件、同一源哈希和同一帧表；独立片头不属于用户交付。不得读取、校验、归档、复制或消费旧共享 `opening.mp4`、`topicCover.png`，不得建立旧 `OPEN-01` 或主题卡派生。
- 锁定口播及分镜中的字幕源文本保持原样；字幕 cue 统一删除所有 Unicode `General_Category=P*` 标点并规范空白，保存 `source_text` 与 `display_text` 两份证据。`caption_free_only` 只把 cue 用作计时/审计数据；`captioned_only` 用唯一版本化字幕组件按真实旁白时间把精确 `display_text` 烧录在底部安全区；`both` 从同一公共合成分别生成两套，除字幕层外的输入、时序、音频、BGM、视觉顺序必须一致。所有 MP4 都保持零字幕流且不交付字幕 sidecar。经分镜批准的数据标签、对比/警示标题和封面文字不属于旁白字幕。
- 可见文字字段在 Per-Shot Visual Direction Review v3 内记录路线解析后的最终结果。批准行仅允许 `none` 或 `required`；白猫 `imagegen` 强制为 `none`、文字及位置为空，且不得有顶部标题。无白猫 imagegen、Ian、Ink Doodle Knowledge Card、Whiteboard 各按本路线合同生成并审批文字。Ian 是结构图默认推荐，`ink-doodle-knowledge-card` 是显式可选路线；`doodle-slides` 仅保留历史只读。视觉阶段不得二次改变语义，assembly 不得新建、改写或删除通用标题层。
- Remotion 渲染规则 `ian-full-frame-mask-sweep-v1` 只适用于 `visual_generation_route: ian-handdrawn-ppt`：分镜大于 3 秒时遮罩滑动时长等于实际分镜时长减 3 秒，最后完整图片停留 3 秒；分镜小于或等于 3 秒时不创建动画，按实际时长直接显示完整图片。非 Ian 分镜不自动使用该组件或规则。
- 普通边界使用 `scene-transition-v3`：源生图路线的匹配规则优先；共享语义映射只作 fallback。所有最终 kind/options 仍须注册、经共享 renderer 执行、显式审核并绑定哈希；可见转场 0.3–0.6 秒，默认 0.4 秒/12 帧。
- 新建或修改镜头使用 `per-shot-visual-direction-review-v3`；完成且未改的 v1/v2 项目不批量迁移。机器 `scene_class` 仅两值，细类另记；`comic-imagegen` 仅保留历史只读解析，不得进入新建、修改或 revoice。
- 版本政策固定为：新写入与重开镜头只准 v3；v1/v2 仅在已完成 episode、素材与审批均未改变时以 `legacy_read_only` 读取。旧镜头一旦修改，受影响的当前映射必须升级为 v3，不能再用旧 schema 写回。
- Whiteboard 新标注使用 `whiteboard-annotation-v2`，内部不再另造枚举，直接采用 v3 的 `none | required`；验证器必须从磁盘重读 v3，并核对路径、文件哈希、map hash、镜头、精确文字与位置。旧 v1 只读。
- 白猫只使用规范角色源并保留身份/动作体系，活动路线仅为 `imagegen` 或 `xuan-paper-diorama`；两者均强制无可见文字。
- Baoyu 仅固定提取 commit `6b7a2e417500561a5ecdd0b168332f4142584617` 的 MIT 视觉规划规则：article-illustrator 提供视觉化建议，comic 提供叙事计划/可选生产路线，infographic/slide-deck/XHS 仅提供分类、密度、版式和兼容矩阵；不安装上游、不引入 Bun/PDF/批量/外部后端。Diagram 延后为独立安全栅格路线。
- 所有生图、动作子图、数据/转场图、封面标准化图、静帧、预览、接触表和视频统一使用 1920×1080、16:9 横版画布；共享封面原图保留实测源尺寸，仅允许按 `cover-only-v1` 生成确定性 1920×1080 衍生图。验证阶段输出 30 fps、H.264 横版主片。旧 9:16 素材不得通过拉伸、补边或嵌套冒充合规，必须重新生成或重新构图。
- 母图派生的动作子图即使各自从同一未修改母图独立生成，也必须按分镜顺序逐对验证动作方向、朝向、重心转移、肢体轨迹、接触点、道具/零钱包位置及因果关系；仅角色一致但动作链不连贯的素材不得进入合成。
- 新建或重规划镜头使用 `action-state-schedule-v3`：`stateful` 为 2–4 张完整场景状态图，默认 2–3 张；第 4 张须对应第四个独立旁白语义和非重复结果。`hero_pose` 为 1 张背景加 4–6 张姿态图，通常 4–5 张；超过 5 个连续状态先评估拆镜，不能自然拆分时才以精确方案哈希取得批准。每个状态绑定锁稿 UTF-8 字节范围和真实音频入点，目标状态至少净展示 15 帧。镜内 `N-1` 条转场默认 `cut`；`watercolor-bloom` 仅在明确选择后使用 18 帧。v2 原公式与强制水彩只保留给未修改历史项目。
- `visual-asset-review-v2` 默认 `hybrid_batch_v1`、四张一批；strict 屏障和队尾提前截批。批次只减少暂停频率，不得批量调用生图。批准时必须重读当前磁盘文件、重算 SHA-256/尺寸/批次清单，视觉锁定前及 assembly 前再全量复验；旧逐图/最终批审模式只读兼容。
- BGM 默认关闭：不读取选择器、不查找或复制 BGM、不创建音乐轨，也不主动询问是否开启；只有用户对当前 episode 明确开启后，才在无 BGM 合成时长锁定后加入所选 BGM，且不得因混音改变内容时间轴。
- 只有当前 episode/variant 的活动交付 transaction manifest 与字幕选择要求的完整成片角色完全一致、其中每个版本化完整成片都通过探测和完整解码且外部副本校验和匹配，并且对应的内部独立片头 QA 文件通过前缀比较后，才算完成；`caption_free_only` 和 `captioned_only` 各列出并交付 1 个 MP4，`both` 列出并交付 2 个 MP4。交付 manifest 绝不列入独立片头。共享目录里的历史版本或其他项目文件不参与集合比较，也不得清理。

## 回滚原则

输入发生变化时，只回滚到最小必要阶段，并让所有依赖旧输入的下游产物失效：

- 未完成 episode 的已解析源文件校验和变化：保留旧候选，保存并校验新版本候选，回到 Gate 2，使旧审计、批准、锁稿、音频验证及全部下游依赖失效；已完成 episode 保持不变，按新文字重做须新建 `new_video`。
- 脚本或口述不匹配：回到 Gate 2 或音频验证。
- 首句文字或提取主题变化：回到 Gate 2，并使 `OPEN-00` 分镜批准、片头计时/组件和当前模式要求的全部母版/片头角色失效；共享封面原字节未变时保留。
- 首句结束帧变化：重做片头计时、分镜 Review、片头组件和当前模式要求的全部母版/片头角色；输入未变的普通视觉素材可保留。
- 音频修复或时长变化：重做字幕、分镜时间、动作计划、合成、与当前模式相符的最终音频组合和渲染；disabled 模式不得进入 BGM 分支。
- 合规换音色派生版本的音频时长变化：保留原项目和原视觉批准，只让该派生版本的新音频、重定时分镜及其 Review、视觉绑定、合成、接触表和当前模式要求的全部母版/片头角色失效并重做。
- 字幕 cue、字幕组件或字幕样式/排版指纹变化：重做字幕显示文本及受影响的分镜/审计校验，只让输入指纹变化的有字幕母版、片头、接触表和交付失效；输入未变的无字幕产物可保留。若分镜文件字节变化，则按分镜变更规则回滚。
- 任何分镜文本、语义、计时或结构修改（包括 Review 修改要求）：产生新校验和，使旧 Storyboard Review 批准和所有依赖旧分镜的视觉及下游产物失效；白猫决定、路线、兼容性或逐镜映射校验和变化时，受影响镜头先回到 Per-Shot Visual Direction Review，并使其素材族及真实下游消费者失效；边界身份、转场种类、必填参数或时长变化时，只让对应转场行回到待确认。两类映射均重新锁定后再完成分镜 QA、展示与 Review。
- 画布规格变化或活动素材仍为 9:16：使所有不匹配的图片、封面标准化图、衍生文件及下游合成失效，原生重做为 1920×1080。
- `cover.png` 哈希、尺寸、像素格式、宽高比、解码结果或确定性裁切输入变化：重做封面归档/标准化图、`OPEN-00` 分镜 Review、片头组件和当前模式要求的全部母版/片头角色；保留输入未变的普通视觉素材。
- 角色、插画或数据问题：只重做受影响素材及下游渲染。
- 动作链连续性问题：只重做受影响的动作族及下游渲染，再跑逐相邻状态和计时预览 QA。
- 无字幕角色意外出现旁白字幕，或有字幕角色缺失、重复、错字、提前/延后显示字幕：只让受影响字幕角色失效，除非证据表明公共合成已变化；任何角色出现字幕流，或出现构图、标题、转场、运动问题，则回到公共无 BGM 合成。
- 用户改变最终字幕交付选择：保留公共合成和仍有效的既有完整成片/内部片头 QA 角色，只补渲染和验证新需要的角色，并新建活动交付 transaction manifest，使其严格等于新的完整成片角色集合；独立片头角色不进入 manifest，共享目录里的旧版与其他项目文件不计入比较，也不得删除。
- 用户明确切换 BGM 模式或启用模式下出现 BGM 问题：合成时长不变时保留基础片，只重做 BGM 分支、最终渲染和对应 QA。

## 后续维护约定

普通流程规则更新不再建立或恢复独立的 `workflows/whole-workflow.md`，也不把详细规则重复写进多个 `SKILL.md`。

1. 修改某个节点时，只更新该节点 Skill 的相关 `references/`。
2. 同步更新本文件中的中文摘要。
3. 如果改动影响阶段顺序、Gate、状态字段、交接条件、阻断或回滚，再同步更新 `workflow-state-machine.md`。
4. `SKILL.md` 保持为稳定入口和 reference 导航；只有 Skill 名称、触发范围、节点路由或 reference 索引本身变化时才需要修改。

# 知识视频完整工作流简表

## 文件定位

`$run-knowledge-video` 是端到端总编排 Skill，负责恢复状态、调用节点 Skill、控制 Gate、处理回滚并完成最终交付。

- 本文件：面向人阅读的中文流程摘要和维护地图。
- `workflow-state-machine.md`：阶段顺序、状态证据、Gate、阻断与回滚的执行依据。
- 各节点 Skill 的 `references/`：对应阶段的详细业务和制作规则。

## 当前流程

| 阶段 | 调用节点 Skill | 主要工作 | 阶段结果 |
|---|---|---|---|
| 0. 工程 workspace | `$run-knowledge-video` 编排器 | 先判断是新视频还是恢复任务；新视频按 `topic1` 的目录骨架创建唯一的新 `topic<N>`，恢复任务只复用状态清单唯一匹配的原目录 | 得到隔离、可恢复且目录合规的单集工程 |
| 1. 选题与 Gate 1 | `$discover-video-topics` | 从当天或最近一期本地选题文件读取候选，或者只校验用户直接提供的题目；检查范围、证据、安全和白猫视觉可行性；幂等记录已选历史 | 锁定一个选题及其来源信息 |
| 2. 定位现成口播稿 | `$run-knowledge-video` 编排器 | 按专业术语或主题关键词，在 `script-resource` 中确定唯一真实目录和唯一 `*_口播稿.txt`；拒绝软链接、缺失和歧义；保存同哈希版本化副本 | 得到可审计的口播候选稿 |
| 3. 口播审计与 Gate 2 | `$validate-video-narration` | 用英文权威资料核验事实、证据边界和平台风险；记录候选稿第一完整句的准确字节范围供片头计时，不检查固定品牌措辞，也不从首句提取主题；展示完整原稿；不静默改写；等待用户明确批准准确文本 | 锁定不可变的最终口播稿及第一完整句 |
| 4. 生成发布封面并选择视频风格 | `$imagegen-calligraphy-cover`、`$run-knowledge-video` | 先以开放、不受预设限制的方式独立生成 16:9、9:16、4:3 封面；Codex 按用户委托验收并展示，不请求封面批准。随后让用户从当前封面风格、三种核心风格和已注册全局风格中选择；选择当前封面风格时再问仅本期或加入全局 | 锁定发布封面包、不可变单集风格快照与 cohesion |
| 5. 选择并验证音频来源 | `$validate-video-narration` | 风格、视觉密度与审批模式锁定后，显式选择 `colocated_voice` 或 `edge_tts`。前者只查找已确定主题目录顶层的 `voice.mp3` 或唯一 `voice*.mp3`；后者只用 `zh-CN-YunjianNeural`、`+20%` 生成版本化音频。两条路线均须完整解码、逐字转写对照并锁定真实时长与首句结束帧 | 锁定唯一旁白主音轨、来源证据、真实时长和首句结束帧 |
| 6. 音频定时分镜、视觉方向、整批可见文字、逐边界转场与 Review | `$build-video-storyboard` | 七列分镜表显示每镜精确秒数；v3 将同一风格与 profile/cohesion SHA 写入每镜，白猫仅走对应 ImageGen treatment；Ian 保持自身分层语法，只继承色板、明度与留白；发布封面不得进入任何行；所有可见文字整批批准 | 锁定分镜、视觉方向、整批文字、Ian 分层计划、转场与校验和 |
| 7. 视觉素材生产 | `$produce-video-visuals` | 按已批路线逐项生产与 QA；ImageGen 消费完整单集风格快照，Ian 等固定路线仅适配色板、明度与留白；发布封面不进入生产队列或统一素材审核页 | 锁定逐项/逐包字节证据与批次清单 |
| 8. 合成、最终字幕交付选择与交付 | `$assemble-video-master` | Ian 背景与元素固定不动，仅按口播节奏执行已批入场；镜内其他路线按已批映射，镜间 `scene-transition-v3` 独立执行；S01 与旁白从第 0 帧开始 | 按字幕选择完成视频交付事务 |
| 9. 交付后 BGM 推荐 | `$short-video-bgm` | 分析交付成片、主题、口播、分镜、情绪弧、节奏与授权边界；实时核验曲目页和授权页 | 交付视频后列出 3–5 首带直接试听链接的候选 |

若已完成一期所用的本地口播原稿后来被修改，并要按新文字重新制作，应启动标准 `new_video`：新建 `topic<N>` workspace，重新执行 Gate 1、脚本解析与审计、Gate 2、音频验证、分镜、视觉审核和交付。已完成 episode 继续绑定其归档锁稿，不因脚本库后续修改而变化；同一题目在历史记录中的删除线仅作提示，仍可再次选择。文字变化不得走 `revoice_variant`。

## 已完成项目的换音色派生版本

当原 topic 已完成、用户只想换音色并复用原图片与画面顺序时，使用同一 episode workspace，以 `resume_mode: revoice_variant` 运行派生分支，不创建新 `topic<N>`：

1. 验证原锁定稿、原分镜、全部逐图批准、视觉清单及已交付成片的路径和校验和。
2. 用户明确指定并授权读取原主题目录顶层的一个 `voice*.mp3`。新音频必须逐字保持原锁定稿的口述内容与顺序；Skill 不调用 TTS。
3. 根据新音频的真实词句时间戳，把原分镜每一行的精确文本跨度重新对齐。禁止用新旧总时长比例整体缩放时间轴。
4. 锁定原镜头/素材/状态数量与顺序及字节、封面、视觉说明、构图、白猫、路线、结构、处理配置，以及父项目每个转场的 kind/options/duration/frame count/推荐来源/审批证据；只允许重算旁白、镜头和边界放置等明确许可的时间字段。任何转场参数或视觉合同变化退出纯重定时分支；包含 `comic-imagegen` 的历史父项目保持只读，不能进入 revoice。
5. 展示新的重定时七列 Summary 分镜（含精确三位小数秒数）和新旁白，重新完成 Storyboard Review。随后建立 `revoice-visual-binding`，证明继续使用的是原视觉清单、原逐图批准和锁定的路线映射；若包含本地视频，只按新目标帧重算播放速率，源字节不变；不调用 `$produce-video-visuals`，也不重复逐图审核。
6. 从原始视觉素材与新时间表重建公共合成并锁定时长，再为该派生版本重新执行最终字幕交付选择；不得继承父版本的选择，也不得只给旧编码成片换音轨。按选择重新渲染完整成片和内部片头 QA 文件，用同时带派生版本与字幕角色标识的新文件名只交付完整成片，保留所有原文件。交付事务通过后仍须调用 `$short-video-bgm` 完成交付后推荐，才算派生流程结束。

Ian 父镜头必须已采用活动 v2 分层包与入场效果图；保留全部包字节、SVG 路径、效果类型/参数、音效身份/裁切/增益、层序、语义和口播字节范围，只按新音频真实时点重算原有层的入场帧与 cue sample。旧合同的已完成项目保持历史只读。

## 用户交互边界

共有六个强制内容审核节点：

1. **Gate 1：选题确认。** 用户选择本地候选，或直接提交自定义选题。
2. **Gate 2：口播稿确认。** 用户明确批准经过审计的准确文本。
3. **Per-Shot Visual Direction Review：逐镜视觉方向确认。** 用七列表单锁定画面、白猫、路线和可见文字候选；文字候选须是简练总结，不得把口播句直接搬上画面。该节点只确定候选，不批准可见文字。`local-video-file` 仍须逐镜填写绝对 `.mp4` 路径；结构合并、画面、白猫、路线或文字候选变化均重算对应映射。
4. **Complete Visible Text Batch Review：整批可见文字确认。** 把全部 active 生成镜头按顺序列成一个 `visible-text-batch-review-v1` 清单，连 `none` 行也包含；展示完整清单与唯一哈希后暂停。用户只需一次批准整个列表，不逐镜批准；行内不得存批准状态、批准消息或时间；one-click 也不能跳过。任一文字、位置、行序、分镜或方向哈希变化，都要重新展示并整批批准新列表。
5. **Per-Boundary Transition Review：逐边界转场确认。** 仅在整批可见文字批准后开始。最终分镜 QA 前，先按源镜头生图路线自身定义解析推荐；无匹配规则时才使用共享语义 fallback。必须展示推荐来源/规则、确切种类、必填参数、0.3–0.6 秒时长和理由。用户可以一次明确批准完整映射，也可逐条决定；未展示的默认、`你看着办`、`继续` 或笼统授权不算选择。任何最终选择仍须由共享 catalog、renderer 和测试支持，不能替换成近似效果。
6. **Storyboard Review：分镜脚本确认。** 视觉方向、整批可见文字和转场映射全部锁定并写入最终分镜后，必须展示含每镜精确秒数的完整七列分镜脚本和已验证旁白音频并暂停；它只批准当前 Markdown 校验和，不能代替前述审批。只有用户明确批准当前分镜校验和后，才能生成或修改视觉资产。若用户要求修改，修改后的新版本必须重新校验并再次 Review；文字变化先重做整批文字审批，转场变化先重开受影响边界行。

Ian 知识视频镜头固定走 `ian-knowledge-video-layered-scene-v2`：无字的完整 Ian 母图、静止背景、全画布透明语义层、文字与复合图规则不变。装配前另建 `ian-layered-entry-effects-v2`：按语义元素类选择 8 帧轻落位、12 帧 SVG 描边/路径生长或带理由的纯渐显；每镜最多两种运动语言。多层镜头只给 2–3 个关键层配置真实入场音效，其余静音；同一源素材单镜最多两次，相邻有声层音色不同，每个音效写明语义理由，不准仅靠变调或变速伪造变化。音效按素材独立校准，旁白增益恒 1，不归一化；峰值超过 -1 dBFS 时只统一降低音效总线。

视觉锁定后、episode 脚本与共享复用审计前，自动执行 `knowledge-video-sound-design-v2`：S01 第 0 帧、每个后续入镜边界（合并前镜转出与本镜开场）及全部镜内转场（含 `cut`）必须有声，只有片尾净停留豁免；其余可见事件逐项判定有声/静音，抽象口播与名词本身保持静音。先过语义、路线、材质、方向、能量、同步与遮蔽硬门槛，再按不可变策略排序，记录入选与落选原因；同一物理时刻仅可合并兼容事件为一个 cue group，覆盖事件仍全部有声但只渲染一次。必需结构 cue 不占按片长分级的可选预算；强音效间隔不少于 30 帧、任意 30 帧窗口最多 3 个组起点，平均间隔/长空档/音色多样性仅作 QA 提示。缺失角色只从实时核验的 Mixkit 官方页或 Pixabay 后备取得，授权不清即阻断。旁白增益恒 1，初始统一 SFX bus 为 1.12，首次整片渲染前先跑纯音频预检，超出 -1 dBFS 只降低整条 SFX bus；revoice 保留音效身份、选择、组、裁切、增益、归属与同步偏移，只重算帧位。

Gate 2 后先生成并委托验收三张发布封面，再询问视频风格；之后才选择视觉密度、审批模式与旁白来源。旁白来源选择是限定音频获取方式的权限，不是内容审核 Gate。`colocated_voice` 只允许确定性查找已解析主题目录顶层音频；`edge_tts` 只允许通过固定适配器调用 `edge-tts`，使用 `zh-CN-YunjianNeural` 与 `+20%`，缺失依赖或生成失败时阻断，绝不静默改走本地音频。音频验证后推进视觉方向；方向锁定后，必须先把完整可见文字清单集中展示并一次批准，才可推进逐边界转场；转场锁定后再推进 Storyboard Review。分镜版本获批并完成逐图 QA 后，one-click 必须生成绑定当前完整摘要、包含全部当前正文图片的统一 HTML 审核页；发布封面不得进入该页。任一正文图片改动都让旧页失效。只有当前页获批才推进公共合成与时长锁定，然后必须停在最终字幕交付选择：`1. 无字幕；2. 有字幕；3. 有字幕跟无字幕的视频都有`。未收到明确选择不得渲染。

标准旁白与 revoice 的用户原始音频统一存入 `assets/audio/user-source/` 的版本化文件；旁白母带及派生音频存于 `assets/audio/`。不得创建 episode 顶层 `audio/`。

## 工程目录约束

每个全新视频必须在 `leverage-video/src` 下创建一个全新的 `topic<N>` workspace；`N` 取现有 `topic数字` 的最大编号加一。`topic1` 只作为目录结构参考，不复制其中的文件，也不把新视频写回 `topic1`。恢复已有视频时，必须根据 `schema/episode-state.json` 唯一定位并复用原 workspace，不因失败或回滚另建目录。

该约束适用于本项目中任何 Skill 或普通对话发起的知识视频单集产物操作，不只适用于 `$run-knowledge-video`。单独调用节点 Skill 时，必须明确指定或唯一解析已有单集 workspace；零个或多个匹配都要停止询问，不能猜测或另建便利目录。Skill、`AGENTS.md`、共享 Remotion 基础设施、依赖、复用工具和仓库级文档属于工程维护文件，继续保存在各自所属位置。

```text
leverage-video/src/topic<N>/
├── assets/
│   ├── audio/       # 音频、旁白母版、BGM、音效
│   ├── image/       # 图片、封面、静帧、接触表
│   ├── narration/   # 字幕、口播稿、转写、分镜文本、TXT/SRT/VTT
│   └── video/       # 预览、中间成片、最终视频
├── script/          # JS/TS/TSX/MJS/PY 等程序代码
├── schema/          # 所有生成的 JSON、状态与素材清单
└── docs/            # 其余非代码文档、审计与制作记录
```

禁止为了方便在单集工程顶层新增 `work`、`output`、`temp`、`render`、`misc` 等目录。只有工具或明确的素材族确实需要时，才能在上述正确类别内建立用途明确的子目录，并把路径记录到 `schema/episode-state.json`。开始阶段工作前、每次阶段交接时以及声明完成前，都必须运行 `python3 .agents/skills/run-knowledge-video/scripts/validate_episode_workspace.py <episode-workspace>`；非零结果立即阻断，校验器不得自动移动或删除文件。

## 核心锁定规则

- 口播稿执行 `local-script-resource-only-v1`：必须来自 `script-resource` 中唯一定位的现成 `*_口播稿.txt`，来源字段固定为 `script_resource`；缺失时不接受聊天中粘贴的终稿绕过查找，也不自行生成或改写。
- 用户可自行修改已解析原稿；Codex 仅在用户明确要求修改该确切路径并取得所需文件权限后写入。聊天中粘贴的新稿仅是修改建议。未完成 episode 检测到源文件校验和变化时，保存新版本候选并回到 Gate 2，使旧审计、批准、锁稿、音频验证及全部下游依赖失效；已完成 episode 不受后续源文件变化影响。
- 标准流程须先记录 `narration-audio-source-selection-v1`。`colocated_voice` 只检查已解析主题目录顶层，不扫描相邻目录；`edge_tts` 只使用固定 `zh-CN-YunjianNeural`、`+20%` 配置及版本化产物。任何路线失败均阻断，不能静默切换。换音色派生版本仍不调用 TTS。
- 换音色派生版本只接受用户明确点名并授权的同主题目录顶层 `voice*.mp3`。口述文字变化会退出派生分支，须将新文字写入并唯一定位本地原稿后启动全新 `new_video`；视觉顺序、锁定白猫/路线映射或任何图片字节变化则退出派生分支，转入普通视觉修订流程。
- 通过验证的旁白主音轨是分镜、字幕、动作状态、转场和成片时长的唯一依据。
- 口播首句没有固定品牌格式门禁。只保存其准确字节范围与候选校验和，用于旁白校验和片头结束帧；不从首句提取主题。
- 每期在 Gate 2 后用 `publishing-cover-generation-v1` 生成独立构图的 16:9、9:16、4:3 发布封面。三者只供发布与可选风格派生；不得进入分镜、正文素材队列、统一视觉审核页、Remotion、成片前缀、master 或内部 QA 角色。`direct-first-shot-v1` 让 S01 与旁白从第 0 帧开始；`OPEN-00`、旧共享 `cover.png`、`opening.mp4` 和 `topicCover.png` 仅作完成历史，不得被新流程读取或消费。
- 锁定口播及分镜中的字幕源文本保持原样；字幕 cue 统一删除所有 Unicode `General_Category=P*` 标点并规范空白，保存 `source_text` 与 `display_text` 两份证据。`caption_free_only` 只把 cue 用作计时/审计数据；`captioned_only` 用唯一版本化字幕组件按真实旁白时间把精确 `display_text` 烧录在底部安全区；`both` 从同一公共合成分别生成两套，除字幕层外的输入、时序、音频、BGM、视觉顺序必须一致。所有 MP4 都保持零字幕流且不交付字幕 sidecar。经分镜批准的数据标签、对比/警示标题和封面文字不属于旁白字幕。
- Per-Shot Visual Direction Review v3 只记录路线解析后的可见文字候选。`required` 候选须按 `concise-summary-visible-text-v1` 写成简练总结：最多两行、总计不超过 28 个非空白字符，并拒绝口语称呼、填充语、解释性引导和句末口语助词。随后以 `visible-text-batch-review-v1` 把全部镜头一次展示、一次批准；禁止逐镜文字批准，one-click 也必须停。白猫 `imagegen`、宣纸和本地视频仍强制 `none`。视觉阶段及 assembly 不得新建、改写或删除已批文字。
- Ian 活动生产包为 `ian-knowledge-video-layered-scene-v2`；新/修订装配使用 `ian-layered-entry-effects-renderer-v2`。入场图绑定包、节奏、SVG/WAV 字节与固定策略 SHA。轻落位最多 10 px、末帧归零；边缘不足 12 px 改纯渐显；描边与路径生长共用一种运动语言；每镜最多两种运动语言。多层镜头仅 2–3 个关键层有音效，其余静音；同源单镜最多两次，相邻有声音色不同。`scene-transition-v3` 仍独占镜头边界。旧合同仅供已完成历史项目只读。
- 普通边界使用 `scene-transition-v3`：源生图路线的匹配规则优先；共享语义映射只作 fallback。所有最终 kind/options 仍须注册、经共享 renderer 执行、显式审核并绑定哈希；可见转场 0.3–0.6 秒，默认 0.4 秒/12 帧。
- 新建或修改镜头使用 `per-shot-visual-direction-review-v3`；完成且未改的 v1/v2 项目不批量迁移。机器 `scene_class` 仅两值，细类另记；`comic-imagegen` 仅保留历史只读解析，不得进入新建、修改或 revoice。
- 版本政策固定为：新写入与重开镜头只准 v3；v1/v2 仅在已完成 episode、素材与审批均未改变时以 `legacy_read_only` 读取。旧镜头一旦修改，受影响的当前映射必须升级为 v3，不能再用旧 schema 写回。
- Whiteboard 新标注使用 `whiteboard-annotation-v2`，内部不再另造枚举，直接采用 v3 的 `none | required`；验证器必须从磁盘重读 v3，并核对路径、文件哈希、map hash、镜头、精确文字与位置。旧 v1 只读。
- 白猫只使用规范角色源并保留身份/动作体系；新建或修改镜头仅走 `imagegen`，强制无可见文字，并绑定封面生成后显式选择的单集风格快照、profile SHA 与全片 cohesion。宣纸白猫仅作历史只读。
- Baoyu 仅固定提取 commit `6b7a2e417500561a5ecdd0b168332f4142584617` 的 MIT 视觉规划规则：article-illustrator 提供视觉化建议，comic 提供叙事计划/可选生产路线，infographic/slide-deck/XHS 仅提供分类、密度、版式和兼容矩阵；不安装上游、不引入 Bun/PDF/批量/外部后端。Diagram 延后为独立安全栅格路线。
- 所有时间轴视觉、动作子图、数据/转场图、静帧、预览、接触表和视频统一使用 1920×1080、16:9 横版画布；发布封面另有独立生成的 16:9、9:16、4:3 三个画幅，不进入分镜、Remotion、成片前缀或内部 QA 角色。成片按 `direct-first-shot-v1` 让 S01 与旁白从第 0 帧开始。验证阶段输出 30 fps、H.264 横版主片。旧 9:16 正文素材不得通过拉伸、补边或嵌套冒充合规，必须重新生成或重新构图。
- 母图派生的动作子图即使各自从同一未修改母图独立生成，也必须按分镜顺序逐对验证动作方向、朝向、重心转移、肢体轨迹、接触点、道具/零钱包位置及因果关系；仅角色一致但动作链不连贯的素材不得进入合成。
- Gate 2 后依次执行：开放风格生成并委托验收 16:9/9:16/4:3 发布封面；从当前封面风格、三种核心风格及已注册全局风格中显式选择；若为当前封面风格，再选择仅本期或加入全局；然后选择视觉密度 `standard | rich`、审批模式 `manual | one_click`、旁白来源 `colocated_voice | edge_tts`。Gate 1 题目或 Gate 2 变化使封面及全部下游失效；封面变化只在当前单集使用封面派生风格时重开风格及下游；风格变化保留有效锁稿/音频并重问密度。已开始旧项目保持历史兼容，除非明确重建。
- 新建或重规划镜头使用 `storyboard-visual-rhythm-v2` 与 `action-state-schedule-v4`。普通计数不变；富图 stateful 目标 4–6、硬范围 2–6，2–3 须 fallback；富图 hero 为 1 背景+4–13 pose，目标总计 10–12，5–9 须 fallback，13–14 须不可拆分评估与数量理由。背景不进 schedule，镜内转场为 `pose_count-1`；每状态至少 15 clean frames、唯一语义、连续完整 UTF-8 覆盖。v1/v3 仅只读。
- Manual 沿用视觉素材审核节点。One-click 仍必须先停在整批可见文字人工审核，视觉生产后再停在完整精确素材哈希清单人工审核；批准后先问字幕，字幕选择前禁用 still、Studio、preview、composition、render。两种模式都不得绕过 QA。
- BGM 默认关闭：不读取选择器、不查找或复制 BGM、不创建音乐轨，也不主动询问是否开启；只有用户对当前 episode 明确开启后，才在无 BGM 合成时长锁定后加入所选 BGM，且不得因混音改变内容时间轴。
- 交付后推荐与是否把 BGM 混入成片是两件事。每个此后创建的标准或换音色交付事务都必须在交付视频后调用 `$short-video-bgm`：优先分析无字幕母版，否则分析有字幕母版；按主题语义、情绪弧、旁白让位、镜头节奏与授权边界推荐 3–5 首，给真实曲目试听链接、授权链接与商用限制。只推荐，不下载、不混音、不改变或重渲染交付视频。旧的已完成事务不追溯失效。
- 只有当前 episode/variant 的活动交付 transaction manifest 与字幕选择要求的完整成片角色完全一致、其中每个版本化完整成片都通过探测和完整解码且外部副本校验和匹配、对应内部独立片头 QA 文件通过前缀比较，并且交付后 BGM 推荐 JSON/Markdown 证据通过后，才算整期完成；`caption_free_only` 和 `captioned_only` 各列出并交付 1 个 MP4，`both` 列出并交付 2 个 MP4。交付 manifest 绝不列入独立片头。共享目录里的历史版本或其他项目文件不参与集合比较，也不得清理。

## 回滚原则

输入发生变化时，只回滚到最小必要阶段，并让所有依赖旧输入的下游产物失效：

- 未完成 episode 的已解析源文件校验和变化：保留旧候选，保存并校验新版本候选，回到 Gate 2，使旧审计、批准、锁稿、音频验证及全部下游依赖失效；已完成 episode 保持不变，按新文字重做须新建 `new_video`。
- 脚本或口述不匹配：回到 Gate 2 或音频验证。
- 锁定首句字节或其记录的字节范围变化：回到 Gate 2，并使音频计时及全部下游依赖失效；发布封面因绑定 Gate 2 稿件也必须重新生成。
- 首句结束帧变化：重做分镜计时、Review、合成和当前模式要求的全部渲染；输入未变且不依赖计时的普通视觉素材可保留。
- 旁白音频修复、来源选择变化或时长变化：保留有效锁稿，但重做旁白母版、首句边界、字幕、分镜时间、动作计划、合成、与当前模式相符的最终音频组合和渲染；disabled 模式不得进入 BGM 分支。
- 合规换音色派生版本的音频时长变化：保留原项目和原视觉批准，只让该派生版本的新音频、重定时分镜及其 Review、视觉绑定、合成、接触表和当前模式要求的全部母版/片头角色失效并重做。
- 字幕 cue、字幕组件或字幕样式/排版指纹变化：重做字幕显示文本及受影响的分镜/审计校验，只让输入指纹变化的有字幕母版、片头、接触表和交付失效；输入未变的无字幕产物可保留。若分镜文件字节变化，则按分镜变更规则回滚。
- 任何分镜文本、语义、计时或结构修改（包括 Review 修改要求）：产生新校验和，使旧 Storyboard Review 批准和所有依赖旧分镜的视觉及下游产物失效；白猫决定、路线、兼容性或方向映射变化时，受影响镜头先回到 Per-Shot Visual Direction Review；任何可见文字模式、文案、位置、行序、分镜或方向绑定变化，都使整批文字批准失效并须重新展示完整新清单；边界身份、转场种类、必填参数或时长变化时，只让对应转场行回到待确认。全部相关映射重新锁定后再完成分镜 QA、展示与 Review。
- 正文画布规格变化或活动正文素材仍为 9:16：使所有不匹配的正文图片、衍生文件及下游合成失效，原生重做为 1920×1080；独立 9:16 与 4:3 发布封面不受正文画布规则约束。
- 发布封面任一画幅字节或 package 哈希变化：重做该画幅 QA 与封面派生 profile。若当前单集选择封面派生风格，则重开风格、密度及所有视觉下游；若选择独立核心/注册风格，则保留其 checksum-current 单集快照。封面永不使时间轴产生 `OPEN-00`。
- 角色、插画或数据问题：只重做受影响素材及下游渲染。
- 未完成项目的 Ian 单图、平移缩放或 v1 独立成员合同：保留历史文件为 superseded，重开受影响 Ian 镜头的分层计划并按 v2 重新生成无字母图、确定性拆层和完整包审批；使旧 Ian 视觉批准、视觉清单、合成、预览、渲染和交付失效。口播、音频及输入未变的非 Ian 素材可保留。已完成项目原样只读。
- 动作链连续性问题：只重做受影响的动作族及下游渲染，再跑逐相邻状态和计时预览 QA。
- 无字幕角色意外出现旁白字幕，或有字幕角色缺失、重复、错字、提前/延后显示字幕：只让受影响字幕角色失效，除非证据表明公共合成已变化；任何角色出现字幕流，或出现构图、标题、转场、运动问题，则回到公共无 BGM 合成。
- 用户改变最终字幕交付选择：保留公共合成和仍有效的既有完整成片/内部片头 QA 角色，只补渲染和验证新需要的角色，并新建活动交付 transaction manifest，使其严格等于新的完整成片角色集合；独立片头角色不进入 manifest，共享目录里的旧版与其他项目文件不计入比较，也不得删除。
- 用户明确切换 BGM 模式或启用模式下出现 BGM 问题：合成时长不变时保留基础片，只重做 BGM 分支、最终渲染和对应 QA。
- 交付后 BGM 推荐缺失、链接失效或授权边界未核实：完整保留已交付视频与事务，只重做推荐报告；不得因此重渲染或修改成片。

## 后续维护约定

普通流程规则更新不再建立或恢复独立的 `workflows/whole-workflow.md`，也不把详细规则重复写进多个 `SKILL.md`。

1. 修改某个节点时，只更新该节点 Skill 的相关 `references/`。
2. 同步更新本文件中的中文摘要。
3. 如果改动影响阶段顺序、Gate、状态字段、交接条件、阻断或回滚，再同步更新 `workflow-state-machine.md`。
4. `SKILL.md` 保持为稳定入口和 reference 导航；只有 Skill 名称、触发范围、节点路由或 reference 索引本身变化时才需要修改。

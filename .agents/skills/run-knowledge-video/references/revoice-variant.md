# Completed-episode revoice variant

Use this contract only when a completed knowledge-video episode needs a different voice or timbre while retaining the exact locked narration text and approved visual arrangement.

## Entry and lineage

- Classify the action as `resume` with `resume_mode: revoice_variant`. Resolve exactly one existing episode workspace from `schema/episode-state.json`; never create or clone a topic workspace.
- Require checksum-valid evidence for the locked script, approved storyboard, completed Visual Asset Review, active visual manifest, cover, original narration master, every delivered parent full master named by the parent's `required_delivery_roles`, and every matching internal opening QA render named by the parent's `required_internal_qa_roles`. For a legacy parent with no `caption_delivery`, accept exactly one checksum-valid delivered caption-free master plus its checksum-valid internal or historical caption-free opening QA as `legacy_caption_free_only` lineage; do not use that inference as the derivative's output choice. A partially completed episode is a normal resume, not a revoice variant. A completed parent that predates `cover-only-v1` must migrate its opening through the normal storyboard revision and Review workflow before it can enter this strict visual-sequence-preserving branch.
- Require complete approved v1, v2, or v3 Per-Shot Visual Direction Review evidence for each generated parent shot. Display the exact ordered mapping and lock it; do not ask for or accept a route change. For v2/v3 also lock structure, treatment, legacy Comic/Doodle evidence when present, state order, approved visible text, and local-video source bindings when present. A parent that contains the retired `comic-imagegen` or `doodle-slides` route is historical read-only and cannot create a revoice derivative. If another legacy parent needs a retimed revised storyboard and lacks direction evidence, first present one current-asset route mapping from its approved storyboard and active visual manifest, then obtain explicit Per-Shot Visual Direction Review. The fixed `OPEN-00` row uses `白猫: 不适用` and `分镜生成方式: 固定封面（cover-only-v1）`; every other row requires final approved visual-direction values. Any visual-contract change exits `revoice_variant` and enters normal storyboard revision.
- Allocate a new immutable `variant_id`. Preserve the original state, audio, storyboard, composition, renders, deliveries, and approval evidence; write only new versioned derivative artifacts in the existing fixed workspace categories.
- Record the parent episode ID; parent `caption_delivery.mode` or the narrow legacy classification; parent `required_delivery_roles`; parent `required_internal_qa_roles`; role-keyed full-master render and external-delivery paths/SHA-256 values; role-keyed internal opening-QA paths/SHA-256 values; and exact paths/SHA-256 values for the parent script, storyboard, visual manifest, narration master, cover, and opening source archive. When the parent has `both`, require both delivered masters and both matching internal opening-QA records rather than choosing an arbitrary caption role.

## Resolve replacement narration audio

- Keep Gate 1 and Gate 2 locked. Do not append topic history or re-audit unchanged text.
- Require the user to name one exact top-level filename matching `voice*.mp3` in the already resolved script-resource topic folder. Ask whether that exact file may be inspected, and inspect no audio before explicit permission.
- After permission, resolve only the named file. Reject path separators, symlinks, non-regular or empty files, a file outside the resolved topic folder, and a checksum identical to the parent source audio as a no-op.
- Archive the exact bytes under `assets/audio/user-source/` with a versioned variant filename, verify the copy checksum, and validate it through `$validate-video-narration`. Use the same user-source category as the standard route; never create a top-level episode `audio/`. Do not invoke Voicebox or another TTS provider.
- Fully decode and transcribe the replacement narration. It must contain the same locked spoken words in the same order, with no addition, omission, repetition, or altered number, name, formula, or term. A wording mismatch is not a voice-only derivative. If the user wants revised wording, require it to exist in the uniquely resolved local `*_口播稿.txt`, then start a standard `new_video` in a fresh workspace and preserve the completed parent unchanged.
- Preserve the parent narration master. Lock a new replacement narration master, duration, timestamped transcript, and first-sentence end frame as timing authority for this variant only.

## Lock the visual sequence

Build `visual_sequence_lock` from the parent approved storyboard and active visual manifest before retiming. For every row, preserve:

- row count, shot ID, row order, scene class, semantic beat, and exact `source_text`;
- asset/state-family IDs, v3 semantic states and exact narration-byte ranges, ordered asset paths/SHA-256 values, motion tier, and every intra-shot effect; for Whiteboard, source/normalized PNG, annotation JSON, preview PNG, silent MP4, and element-order checksums;
- visual description, approved visible-text mode and exact text, crop, camera/framing, internal-motion kind, complete approved white-cat/route/structure/treatment mapping and v1/v2/v3 direction-selection evidence, complete parent transition kind, options, `duration_seconds`, `duration_in_frames`, recommendation authority, and user-selection evidence, and sound-effect cue identity;
- cover path/checksum, normalized opening-cover path/checksum, canvas fingerprint, and BGM mode.

Serialize the ordered field set as UTF-8 JSON with object keys sorted, array order preserved, `ensure_ascii=false`, and compact separators, then record its SHA-256. Recompute and compare it before Storyboard Review, before assembly, and before delivery. Any mismatch exits `revoice_variant`; do not regenerate, edit, reorder, replace, crop, or reapprove images inside this branch.

## Retime against exact text

- Invoke `$build-video-storyboard` in `retiming-only` mode. Copy the parent approved storyboard to a new versioned Markdown file under `assets/narration/`; never edit the parent file. Produce the deterministic review-only seven-column Summary `镜头｜时长（秒）｜画面｜白猫｜分镜生成方式｜可见文字｜锁稿原文` from unchanged locked row fields, the locked visual-direction mapping, and newly computed exact frame durations. This format-only duplicate is outside `visual_sequence_lock` and changes no authoritative visual field. For a legacy parent, this insertion follows—not replaces—the explicit current-asset visual-direction confirmation.
- Align the replacement narration transcript to the locked script and each existing row's exact, ordered text span. Derive every new narration in/out boundary from that span's real timestamp. Do not scale the old timeline by total-duration ratio and do not estimate from reading speed.
- Keep every immutable `visual_sequence_lock` field unchanged. For v3 recompute only narration timestamps, shot/boundary placement, state entry/end frames from locked byte ranges, `first_sentence_end_frame`, cover hold, internal-motion timing, existing sound-effect cue times, and retained local-video playback rate. Preserve every intra-shot effect and inter-shot transition field/evidence byte-for-byte. For Whiteboard, map each locked annotation text span to one contiguous timing segment while keeping MP4 bytes unchanged. Any state identity/semantic/asset/effect or transition change exits this route.
- Keep the exact cover path/checksum unchanged, keep narration at frame 0, set `episode_opening_frames = first_sentence_end_frame`, set `final_master_frames = replacement_narration_master_frames`, and recompute the internal per-topic opening from the replacement first-sentence end frame.
- Revalidate seven-column Summary-table equality including exact frame-derived seconds, full narration coverage, exact row order, timing monotonicity, exact parent-transition equality, transition bounds, action-state cadence, maximum holds, semantic A/V correspondence, and the visual-direction map digest. If any new shot is shorter than its locked transition, or the new timing otherwise cannot fit the locked states and transitions, block the variant and ask the user to choose another voice/speed or exit revoice for the normal storyboard revision, Per-Boundary Transition Review, and Storyboard Review sequence.

## Review and bind reused visuals

- Present the new retiming-only storyboard and replacement narration master as the two workcard artifacts. Require a fresh Storyboard Review bound to their exact checksums.
- A timing change invalidates the parent storyboard approval for the derivative, but not unchanged visual bytes. Do not call `$produce-video-visuals` or repeat Visual Asset Review when prior approvals match disk and `visual_sequence_lock` passes. Preserve v3 state identity/order/assets/effects; block when any target has fewer than 15 clean frames after its unchanged incoming effect. Historical v2 retains its 18–75-frame mandatory-watercolor limits. A legacy mapping confirmation never authorizes regeneration.
- After Storyboard Review approval, create `schema/revoice-visual-binding-<variant_id>.json`. Record the parent visual manifest path/checksum, parent visual approval evidence, route-review evidence, new storyboard and narration checksums, `visual_sequence_lock` digest/comparison, unchanged canvas/cover/opening evidence, and `reuse_qa: passed`. For Whiteboard include the immutable clip checksum and complete per-element source/output frame and playback-rate mapping.
- Never rewrite the parent visual manifest to pretend it was generated from the replacement audio. `$assemble-video-master` consumes the immutable parent visual manifest together with the new binding and must compare each derivative transition with the exact parent snapshot before composition work.

## Assemble, QA, and deliver

- Rebuild the composition schedule from the replacement narration master and approved retiming-only storyboard while consuming the same locked visual sequence. Lock the caption-neutral composition, then require a fresh Caption Delivery Choice before any final render. Do not inherit the parent's caption-delivery mode, and do not swap an audio stream into the old encoded master.
- Preserve the parent BGM mode. If disabled, access no BGM resource. If enabled, reuse only the already archived, checksum-matching BGM source and the same mix policy after the new composition duration lock; do not resolve a different track.
- Preserve the accepted sound-effect sources and cue identities; retime only their existing semantic cue positions. A cue that no longer maps unambiguously is a blocker.
- Record `caption_delivery.mode`, the exact derivative-specific choice evidence, `required_delivery_roles`, `required_internal_qa_roles`, and a new derivative delivery transaction ID/manifest. Render and repeat complete opening, A/V-sync, action-cadence, visual-sequence, role-appropriate caption, technical, contact-sheet, and delivery QA for every selected full master and its internal opening-QA counterpart. Compare the ordered visual sequence of each derivative against `visual_sequence_lock`; a burned-in narration-caption layer is an output-mode overlay and does not alter that lock.
- Use new versioned filenames containing the variant identity and caption role for every selected full master and internal per-topic opening. Never overwrite the parent render or delivery. Deliver the replacement narration master and role-appropriate contact-sheet evidence alongside exactly the selected verified full-master MP4 role set. Keep every standalone per-topic opening inside the episode workspace as internal opening QA and do not copy or return it.

## Blockers

Stop the revoice branch when the parent is incomplete, contains a retired route, lacks complete review/transition evidence, current-asset mapping, delivery lineage, checksum/image approval, authorized replacement audio, identical spoken text, or unambiguous text-span alignment; when any intra/inter-shot effect differs, a locked timing constraint or 15-frame clean hold fails, the visual sequence changes, Caption Delivery Choice is missing, delivery roles drift, or an output would overwrite its parent. Apply historical v2's 18–75-frame rule only to a v2 parent. Route substantive script or visual/effect changes through the normal review workflow.

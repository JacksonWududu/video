# Knowledge-video state machine

## Episode workspace contract

Resolve all paths from the repository root. Treat `leverage-video/src` as the only parent for episode workspaces.

- Before writing, classify the action as `new_video`, `resume`, `standalone_phase`, or `project_maintenance`.
- For `new_video`, inspect only real direct child directories matching `topic[0-9]+`, choose `topic<N>` where `N` is one greater than the highest existing numeric suffix, verify that the target does not exist, and create exactly one fresh workspace. Use `leverage-video/src/topic1` only as the structural reference; do not copy its files or write a new episode into `topic1`.
- For `resume`, locate exactly one existing workspace whose `schema/episode-state.json` identifies the episode. Reuse it and reconstruct state from the manifest and checksums. Stop on zero or multiple matches rather than guessing or creating another workspace.
- For `standalone_phase`, use an explicitly identified existing episode workspace or resolve exactly one existing workspace from its `schema/episode-state.json`. Stop and ask the user on zero or multiple matches; do not guess, create a new episode, or create a convenience directory.
- For `project_maintenance`, keep Skill definitions, project instructions, shared Remotion infrastructure, dependencies, reusable tooling, and repository-level documentation in their owning project locations. Do not select or create an episode workspace.
- Create only this fixed initial directory skeleton:

```text
leverage-video/src/topic<N>/
├── assets/
│   ├── audio/
│   ├── image/
│   ├── narration/
│   └── video/
├── script/
├── schema/
└── docs/
```

- Store immutable user audio sources under `assets/audio/user-source/`; store validated or derived narration masters, BGM copies, sound effects, and generated audio elsewhere under `assets/audio/`. Never create an episode-level `audio/` directory.
- Store generated illustrations, action variants, data graphics, covers, stills, and contact sheets under `assets/image/`.
- Store narration candidates and locks, transcripts, subtitle files, and text storyboard or shot-list files under `assets/narration/`, including the relevant `.txt`, `.srt`, or `.vtt` artifacts.
- Store previews, intermediate renders that must be retained, and final generated videos under `assets/video/`.
- Store generated executable or source code under `script/`, including `.js`, `.ts`, `.tsx`, `.mjs`, `.py`, and other program files.
- Store every generated JSON file under `schema/`, including `episode-state.json`, asset manifests, timing/state data, metadata, and QA JSON.
- Store all other non-code documents under `docs/`, including Markdown audit notes, reports, source maps, and production records that do not belong to the narration-text set.
- Do not create additional top-level workspace folders such as `work`, `output`, `temp`, `render`, or `misc`. Create a nested folder inside the assigned category only when a tool or a meaningful artifact family requires it; use a purpose-specific name and record it in `schema/episode-state.json`.
- Keep workspace references repository-relative in manifests and generated project files. Use absolute paths only for canonical resources outside this repository.
- Run `python3 .agents/skills/run-knowledge-video/scripts/validate_episode_workspace.py <episode-workspace>` before phase work, at every phase handoff, and before claiming completion. Treat a nonzero result as a blocker. The validator reports violations only; it must not move, delete, or rewrite files.
- At each validation checkpoint, verify that every generated file is inside the active episode workspace and in the correct category. Relocate a misplaced artifact before passing the phase; never leave duplicate convenience copies.

## Completed-episode revoice variant route

Use this alternate route only for `action_classification: resume` with `resume_mode: revoice_variant`. Read [revoice-variant.md](revoice-variant.md) completely before action.

1. Resolve exactly one completed parent episode workspace and require complete checksum-valid lineage. Preserve every parent artifact and allocate a new `variant_id`. A parent predating `cover-only-v1` must migrate its opening normally first. A parent containing retired `comic-imagegen` or `doodle-slides` is historical read-only and cannot enter revoice. For every other parent with checksum-valid v1, v2, or v3 Visual Direction Review, display and lock the complete approved mapping. Any visual-contract change exits `revoice_variant`.
2. Keep Gate 1 and Gate 2 locked and do not append topic history. Require the user to name one exact top-level `voice*.mp3` in the already resolved script-resource topic folder and explicitly permit inspection of that file. Resolve no other audio.
3. Hand the exact file and parent locked script to `$validate-video-narration`. Archive and validate it as replacement narration audio, require identical spoken words and order, and lock a new variant narration master, timestamped transcript, duration, and first-sentence end frame. A text mismatch exits this route; revised narration text must use the uniquely resolved local source and a fresh standard `new_video` workspace while preserving the parent.
4. Compute `visual_sequence_lock` from the parent approved storyboard, density mode, asset counts/order, canonical rhythm/schedule hashes, approved white-cat/route/structure/treatment mapping, complete parent transition evidence, and visual manifest. A revoice variant inherits these fields exactly; changing density, count, order, or either canonical hash fails closed and exits `revoice_variant`. Invoke `$build-video-storyboard` in `retiming-only` mode: preserve every locked text/semantic/visual/order/transition field, map each existing row's exact text span to replacement-audio timestamps, and recompute only allowed timing plus shot/boundary placement fields. A shot shorter than its locked transition blocks revoice. The derived storyboard uses the seven-column Summary, recomputes its read-only exact duration cells, and keeps non-opening white-cat/route cells equal to detailed-row and visual-direction evidence byte-for-byte. A retained local video preserves source bytes and recomputes only its exact target timing/playback rate. Global duration scaling is forbidden.
5. Present the new storyboard and replacement narration master for Storyboard Review. Set phase `awaiting_revoice_storyboard_review` and stop. Preserve the parent's complete v1/v2/v3 visual-direction and transition-selection mapping/evidence; changes may alter timing fields only. Any requested white-cat, route, visible-text, visual, order, framing, crop, motion-kind, transition kind/options, or asset change exits this route and reopens normal Per-Shot Visual Direction Review and Per-Boundary Transition Review before a new Storyboard Review. Narration-text changes instead require a fresh standard `new_video`.
6. After approval of the exact retimed storyboard bytes, revalidate every parent image checksum and approval plus `visual_sequence_lock`. Create `schema/revoice-visual-binding-<variant_id>.json` linking the immutable parent visual manifest to the new storyboard and narration. Do not call `$produce-video-visuals` or repeat Visual Asset Review.
7. Hand the replacement narration, approved retimed storyboard, parent visual manifest, and passing revoice binding to `$assemble-video-master`. Rebuild and lock the timing schedule and caption-neutral composition from source assets. A parent Ian scene must already use the active layered package: preserve every member byte/order/semantic role and narration-byte range, and retime only its existing layer entry frames from the replacement audio while keeping the fixed eight-frame fades. Rebuild and reapprove the timing-bound plan; invent no layer, transform, mask, or timing branch. A completed historical parent on an old flattened Ian contract cannot create a revoice output without normal-route migration. Preserve every approved incoming `scene-transition-v3`, the parent BGM mode, and existing sound-effect identities; retime only their semantic cues. Require a fresh Caption Delivery Choice before rendering and do not inherit the parent's caption-delivery mode.
8. Render only the derivative's selected full-master roles in `required_delivery_roles` plus their internal opening-QA roles in `required_internal_qa_roles`, complete full technical, visual-order, A/V-sync, opening, role-appropriate caption, render, and delivery QA, and write new versioned outputs without overwriting parent files. Deliver only every checksum-matched full master in `required_delivery_roles`; keep the opening renders inside the episode workspace. Record phase `revoice_variant_delivered` only when the active derivative delivery transaction manifest's role set equals `required_delivery_roles` exactly and contains no opening role.

`ian-knowledge-video-frame-v1`, `ian-static-full-frame-v1`, and `ian-subtle-raster-motion-v1` are completed-history evidence only. Active unfinished/new Ian uses the static layered package and `IanLayeredScene`. No active route consumes the historical mask-sweep module; Ink stays on its approved-PNG-only `GraphicScene` contract. - Adjacent-state action-continuity defect → invalidate the affected action family and downstream renders; regenerate only from the unchanged accepted master, then rerun ordered-pair continuity QA and timed-preview QA before assembly.
- Data value or label defect → invalidate the affected data graphic and downstream renders.
- Missing, stale, wrong, or mismatched Ian layered plan/package; incomplete narration-byte coverage; missing/reordered/changed member; bad alpha role; nondeterministic final composite; inferred or invalid entry frame; any scene/layer transform, mask, parallax, internal cut, non-eight-frame fade, wrong S01 local-frame-0 state, or ordinary Ian entry not owned by its approved `scene-transition-v3` → invalidate the affected Ian package approval, visual manifest, assembly input/plan, composition lock, previews, renders, QA, and delivery. Preserve current narration/audio, unaffected non-Ian assets, and unaffected transition approvals when their fingerprints remain valid. Return timing/range defects to storyboard and pixel/member defects to visual production; rebuild through shared `IanLayeredScene` and rerun package/renderer QA. Completed historical flattened Ian episodes remain read-only and are never silently migrated.
- Wrong frame-0 narration start, hidden opening offset, wrong `OPEN-00 → S01` hard cut, cover/source/archive/normalized mismatch, added cover text/motion, subtitle stream, crop, or transition defect → return to the BGM-free base composition. A missing/extra/wrong burned-in narration caption or caption-component count invalidates only the affected caption role unless evidence shows that the shared base changed; any bottom narration caption in a caption-free role is a defect.
- Missing, pending, `none`, unsupported, option-incomplete, substituted, out-of-range, unbound, or unverified semantic transition decision → preserve approved raster bytes and locked timing, invalidate the active transition-review/assembly-plan passing status plus downstream composition/renders/deliveries, return the affected boundary to Per-Boundary Transition Review, repair through shared `scene-transition-v3`, rerun shared tests and the validator, and capture selected-effect frames or cut-adjacency evidence before composition lock. Never preserve approval across a changed kind, option, duration, boundary identity, catalog checksum, or presented-map checksum.
- Caption Delivery Choice change → preserve the locked composition and all still-valid existing role outputs, derive the new `required_delivery_roles` and `required_internal_qa_roles`, create a new active delivery transaction manifest, render and QA newly required full-master and internal opening-QA roles, and list exactly the new full-master delivery role set in that manifest. Do not list any opening role or no-longer-selected master in the active transaction; if a no-longer-selected master exists, do not delete its historical versioned file from the shared directory.
- Explicit `disabled → enabled` BGM change → preserve the duration-locked base, validate and add BGM, then redo final render and QA.
- Explicit `enabled → disabled` BGM change or enabled-mode BGM defect → preserve the duration-locked base, remove or repair only the BGM branch, then redo final render and mode-appropriate QA.
- Final mux/delivery-copy defect → re-render or re-copy from the last verified source; do not alter upstream content without evidence.

Never retain a downstream artifact whose input fingerprint changed. A revoice binding never rewrites the parent visual manifest or claims that its narration fingerprint changed; it separately proves that the derivative consumes the same semantic text and exact visual sequence with only a new timing dependency.

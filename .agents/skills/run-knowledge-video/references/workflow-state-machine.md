# Knowledge-video state machine

## Episode workspace contract

Resolve all paths from the repository root. Treat `leverage-video/src` as the only parent for episode workspaces.

- Before writing, classify the action as `new_video`, `resume`, `standalone_phase`, or `project_maintenance`.
- For `new_video`, inspect only real direct child directories matching `topic[0-9]+`, choose `topic<N>` where `N` is one greater than the highest existing numeric suffix, verify that the target does not exist, and create exactly one fresh workspace. Use `leverage-video/src/topic1` only as the structural reference; do not copy its files or write a new episode into `topic1`.
- For `resume`, locate exactly one existing workspace whose `schema/episode-state.json` identifies the episode. Reuse it and reconstruct state from the manifest and checksums. Stop on zero or multiple matches rather than guessing or creating another workspace.
- For `standalone_phase`, use an explicitly identified existing episode workspace or resolve exactly one existing workspace from its `schema/episode-state.json`. Stop and ask the user on zero or multiple matches; do not guess, create a new episode, or create a convenience directory.
- For `project_maintenance`, keep Skill definitions, project instructions, shared Remotion infrastructure, dependencies, reusable tooling, and repository-level documentation in their owning project locations. Do not select or create an episode workspace.
- Create only this fixed initial directory skeleton:

```text
leverage-video/src/topic<N>/
├── assets/
│   ├── audio/
│   ├── image/
│   ├── narration/
│   └── video/
├── script/
├── schema/
└── docs/
```

- Store immutable user audio sources under `assets/audio/user-source/`; store validated or derived narration masters, BGM copies, sound effects, and generated audio elsewhere under `assets/audio/`. Never create an episode-level `audio/` directory.
- Store generated illustrations, action variants, data graphics, covers, stills, and contact sheets under `assets/image/`.
- Store narration candidates and locks, transcripts, subtitle files, and text storyboard or shot-list files under `assets/narration/`, including the relevant `.txt`, `.srt`, or `.vtt` artifacts.
- Store previews, intermediate renders that must be retained, and final generated videos under `assets/video/`.
- Store generated executable or source code under `script/`, including `.js`, `.ts`, `.tsx`, `.mjs`, `.py`, and other program files.
- Store every generated JSON file under `schema/`, including `episode-state.json`, asset manifests, timing/state data, metadata, and QA JSON.
- Store all other non-code documents under `docs/`, including Markdown audit notes, reports, source maps, and production records that do not belong to the narration-text set.
- Do not create additional top-level workspace folders such as `work`, `output`, `temp`, `render`, or `misc`. Create a nested folder inside the assigned category only when a tool or a meaningful artifact family requires it; use a purpose-specific name and record it in `schema/episode-state.json`.
- Keep workspace references repository-relative in manifests and generated project files. Use absolute paths only for canonical resources outside this repository.
- Run `python3 .agents/skills/run-knowledge-video/scripts/validate_episode_workspace.py <episode-workspace>` before phase work, at every phase handoff, and before claiming completion. Treat a nonzero result as a blocker. The validator reports violations only; it must not move, delete, or rewrite files.
- At each validation checkpoint, verify that every generated file is inside the active episode workspace and in the correct category. Relocate a misplaced artifact before passing the phase; never leave duplicate convenience copies.

## Completed-episode revoice variant route

Use this alternate route only for `action_classification: resume` with `resume_mode: revoice_variant`. Read [revoice-variant.md](revoice-variant.md) completely before action.

1. Resolve exactly one completed parent episode workspace and require complete checksum-valid lineage. Preserve every parent artifact and allocate a new `variant_id`. A parent predating `cover-only-v1` must migrate its opening normally first. A parent containing retired `comic-imagegen` or `doodle-slides` is historical read-only and cannot enter revoice. For every other parent with checksum-valid v1, v2, or v3 Visual Direction Review, display and lock the complete approved mapping. Any visual-contract change exits `revoice_variant`.
2. Keep Gate 1 and Gate 2 locked and do not append topic history. Require the user to name one exact top-level `voice*.mp3` in the already resolved script-resource topic folder and explicitly permit inspection of that file. Resolve no other audio.
3. Hand the exact file and parent locked script to `$validate-video-narration`. Archive and validate it as replacement narration audio, require identical spoken words and order, and lock a new variant narration master, timestamped transcript, duration, and first-sentence end frame. A text mismatch exits this route; revised narration text must use the uniquely resolved local source and a fresh standard `new_video` workspace while preserving the parent.
4. Compute `visual_sequence_lock` from the parent approved storyboard, approved white-cat/route/structure/treatment mapping, complete parent transition kind/options/duration seconds/duration frames/recommendation authority/selection evidence, and visual manifest. Invoke `$build-video-storyboard` in `retiming-only` mode: preserve every locked text/semantic/visual/order/transition field, map each existing row's exact text span to replacement-audio timestamps, and recompute only allowed timing plus shot/boundary placement fields. A shot shorter than its locked transition blocks revoice. The derived storyboard uses the six-column Summary and its non-opening white-cat/route cells must equal detailed-row and visual-direction evidence byte-for-byte. Global duration scaling is forbidden.
5. Present the new storyboard and replacement narration master for Storyboard Review. Set phase `awaiting_revoice_storyboard_review` and stop. Preserve the parent's complete v1/v2/v3 visual-direction and transition-selection mapping/evidence; changes may alter timing fields only. Any requested white-cat, route, visible-text, visual, order, framing, crop, motion-kind, transition kind/options, or asset change exits this route and reopens normal Per-Shot Visual Direction Review and Per-Boundary Transition Review before a new Storyboard Review. Narration-text changes instead require a fresh standard `new_video`.
6. After approval of the exact retimed storyboard bytes, revalidate every parent image checksum and approval plus `visual_sequence_lock`. Create `schema/revoice-visual-binding-<variant_id>.json` linking the immutable parent visual manifest to the new storyboard and narration. Do not call `$produce-video-visuals` or repeat Visual Asset Review.
7. Hand the replacement narration, approved retimed storyboard, parent visual manifest, and passing revoice binding to `$assemble-video-master`. Rebuild and lock the timing schedule and caption-neutral composition from source assets. Preserve `ian-full-frame-mask-sweep-v1` as the motion kind for every bound Ian raster, but recompute its static-versus-sweep branch and frame counts from each newly approved shot duration; crossing the three-second boundary remains the same deterministic rule, not a visual or motion-kind change. Preserve the parent BGM mode and existing sound-effect identities; retime only their semantic cues. Require a fresh Caption Delivery Choice before rendering and do not inherit the parent's caption-delivery mode.
8. Render only the derivative's selected full-master roles in `required_delivery_roles` plus their internal opening-QA roles in `required_internal_qa_roles`, complete full technical, visual-order, A/V-sync, opening, role-appropriate caption, render, and delivery QA, and write new versioned outputs without overwriting parent files. Deliver only every checksum-matched full master in `required_delivery_roles`; keep the opening renders inside the episode workspace. Record phase `revoice_variant_delivered` only when the active derivative delivery transaction manifest's role set equals `required_delivery_roles` exactly and contains no opening role.

The Ian mask-sweep rule does not apply to any non-Ian visual; Ink stays on its approved-PNG-only `GraphicScene` contract. Historical unchanged Doodle evidence keeps its read-only `DoodleScene` consumer.

- While a standard-route episode is unfinished, revalidate the source path/checksum on resume and before every phase handoff. A changed checksum invalidates the prior candidate audit, Gate 2 approval, locked script, narration/audio validation, and every downstream dependent artifact; preserve the superseded candidate, ingest the current source as a new version, and restart at Gate 2.
- A later edit to the local source used by a completed episode does not alter that completed episode's archived lock. Producing the revised wording requires `new_video`: create a fresh workspace, allow the same historically marked topic to be selected again, resolve the current local source, and rerun every Gate and production phase. Keep the completed workspace unchanged. This route is never `revoice_variant` because revoice requires identical words.
- A legacy state whose narration origin is `user_supplied` must fail closed until the text exists in one uniquely resolved local `*_口播稿.txt`; never coerce the legacy value or guess a topic folder.
- A completed-episode `revoice_variant` does not reopen Gate 1 or Gate 2 and does not append topic history. It is valid only while the exact locked script remains unchanged and the replacement speech matches it.
- In the standard route after Gate 2, continue autonomously through narration validation and storyboard construction until the complete Per-Shot Visual Direction Review proposal is ready, then stop for explicit white-cat/route/text selection of every generated shot. Only after that mapping is fully approved and bound into the storyboard may the Per-Boundary Transition Review proposal be presented; only after both mappings are fully approved and bound may final storyboard QA and mandatory Storyboard Review begin. After that exact storyboard version is approved, enforce Visual Asset Review v2 with hybrid batches and strict barriers; no unapproved image or downstream derivative may be produced or consumed. The revoice route instead preserves a parent's approved v1/v2/v3 visual-direction mapping, or first obtains legacy current-asset Visual Direction Review, then follows its timing-only Review and binding steps above.
- Do not inspect audio files before the user explicitly permits the lookup. In the standard route, after permission inspect only real top-level files in the already matched topic folder; prefer exact `voice.mp3`, otherwise require exactly one real regular `voice*.mp3`. In `revoice_variant`, require permission for one exact user-named top-level `voice*.mp3` and inspect only that basename even when other voice files coexist. Reject path separators, symlinks, and non-regular or empty files.
- A missing, inaccessible, empty, symlinked, undecodable, or script-mismatched resolved audio file is a blocker. Report it; never scan unrelated folders, choose by modification time, or synthesize narration.

## Workcard boundary

The workcard has exactly two user-facing artifacts:

1. The final storyboard containing the exact corresponding narration for every shot.
2. The validated final narration audio, or the validated replacement narration master for the active revoice variant.

Keep research notes, source maps, original-audio archives, derived working files, transcription checks, QA reports, and prompt logs internal.

## Rollback matrix

- Resolved source checksum change in an unfinished standard-route episode → preserve the superseded candidate, ingest and checksum a new versioned candidate from the same validated source path, return to Gate 2, and invalidate the prior audit, approval, locked script, narration/audio validation, and every downstream dependent artifact. A completed episode remains bound to its archived lock; revised wording starts a fresh `new_video` workspace.
- Script or spoken-word mismatch → return to Gate 2/audio-first validation and invalidate all timing-derived artifacts.
- Opening-sentence wording or extracted topic change → return to Gate 2, invalidate the `OPEN-00` storyboard row/Review approval, opening timing/component, composition, and every selected full-master/internal-opening-QA role; preserve unchanged cover bytes.
- Narration audio repair or duration change → invalidate subtitles, storyboard timing, state schedules, composition, mode-appropriate final audio combination, and renders; disabled mode must not enter the BGM branch.
- Valid `revoice_variant` audio change with unchanged spoken words → preserve parent artifacts and approved visual bytes; create new variant audio, timing-only storyboard, Storyboard Review evidence, revoice binding, composition, contact sheet, renders, and deliveries. Invalidate only the active derivative artifacts at or after the changed variant input.
- First-sentence end-frame change with unchanged words → invalidate opening timing, storyboard Review approval, opening component, composition, and every selected full-master/internal-opening-QA role; preserve unrelated accepted visual assets whose input fingerprints remain unchanged.
- Internal caption normalization rule, caption source, caption-component version, or caption-style/layout fingerprint change → regenerate and revalidate caption evidence, then invalidate only captioned renders/openings/contact sheets/deliveries whose caption input fingerprint changed. Preserve caption-free outputs when their actual inputs remain unchanged. If the active storyboard bytes change, apply the storyboard-revision rollback instead.
- Any standard-route storyboard text, semantic, timing, or structural revision produces a new SHA-256 and requires fresh Review. Compute a shot-level change set including scene class, visual description, identities, white-cat decision, `visual_structure_id`, `treatment_profile_id`, active route compatibility/selection, state order, text, framing, transition contract, and asset mapping. Return only changed visual contracts to v3 direction review and invalidate their true dependents. Preserve unchanged exact bytes and approvals. Timing-only changes may rebind after semantic/timing QA. Revoice remains governed by its stricter visual-sequence and transition lock.
- Canvas fingerprint change, any portrait visual, or any AI/source raster outside the `0.5%` 16:9 tolerance → invalidate every affected visual, normalized raster, composition, still, preview, contact sheet, and render. Regenerate each affected Ian or Ink data/logic raster only through its currently approved `ian-handdrawn-ppt` or `ink-doodle-knowledge-card` route; for the deterministic shared cover, recompute only its 1920×1080 scale-to-cover derivative after the same source bytes pass Review. Never stretch or pad.
- Shared `cover.png` checksum, dimensions, pixel format, aspect/decode result, or deterministic crop input change → invalidate its archive/normalized raster, `OPEN-00` storyboard approval, opening component, composition, every selected full-master/internal-opening-QA role, and their contact sheets; preserve unrelated later visuals when their fingerprints remain valid.
- Character identity or illustration defect → invalidate the affected image family, derivatives, and downstream renders only.
- Missing visual approval evidence or changed approved image bytes → invalidate that asset, its true dependents, the affected batch manifest, and downstream consumers; preserve individually approved unchanged bytes. Generation past a strict barrier invalidates the items produced beyond that barrier; other queue-order defects invalidate only improperly generated items, their true dependents, and affected package manifests.
- Adjacent-state action-continuity defect → invalidate the affected action family and downstream renders; regenerate only from the unchanged accepted master, then rerun ordered-pair continuity QA and timed-preview QA before assembly.
- Data value or label defect → invalidate the affected data graphic and downstream renders.
- Missing or wrong `ian-full-frame-mask-sweep-v1` route predicate, shared-component provenance, duration input, branch, sweep/hold timing, mask direction, or final full-raster hold → preserve the approved Ian raster bytes, invalidate the affected shot schedule plus downstream composition/renders, and rebuild from `leverage-video/src/shared/full-frame-mask-sweep`. Do not apply that repair to non-Ian shots.
- Wrong frame-0 narration start, hidden opening offset, wrong `OPEN-00 → S01` hard cut, cover/source/archive/normalized mismatch, added cover text/motion, subtitle stream, crop, or transition defect → return to the BGM-free base composition. A missing/extra/wrong burned-in narration caption or caption-component count invalidates only the affected caption role unless evidence shows that the shared base changed; any bottom narration caption in a caption-free role is a defect.
- Missing, pending, `none`, unsupported, option-incomplete, substituted, out-of-range, unbound, or unverified semantic transition decision → preserve approved raster bytes and locked timing, invalidate the active transition-review/assembly-plan passing status plus downstream composition/renders/deliveries, return the affected boundary to Per-Boundary Transition Review, repair through shared `scene-transition-v3`, rerun shared tests and the validator, and capture selected-effect frames or cut-adjacency evidence before composition lock. Never preserve approval across a changed kind, option, duration, boundary identity, catalog checksum, or presented-map checksum.
- Caption Delivery Choice change → preserve the locked composition and all still-valid existing role outputs, derive the new `required_delivery_roles` and `required_internal_qa_roles`, create a new active delivery transaction manifest, render and QA newly required full-master and internal opening-QA roles, and list exactly the new full-master delivery role set in that manifest. Do not list any opening role or no-longer-selected master in the active transaction; if a no-longer-selected master exists, do not delete its historical versioned file from the shared directory.
- Explicit `disabled → enabled` BGM change → preserve the duration-locked base, validate and add BGM, then redo final render and QA.
- Explicit `enabled → disabled` BGM change or enabled-mode BGM defect → preserve the duration-locked base, remove or repair only the BGM branch, then redo final render and mode-appropriate QA.
- Final mux/delivery-copy defect → re-render or re-copy from the last verified source; do not alter upstream content without evidence.

Never retain a downstream artifact whose input fingerprint changed. A revoice binding never rewrites the parent visual manifest or claims that its narration fingerprint changed; it separately proves that the derivative consumes the same semantic text and exact visual sequence with only a new timing dependency.

# 创作包输出契约

## 输出位置与版本

唯一生产输出根目录：

`output/codexVoiceScript`

每个选题使用一个同名子目录。选题不得为空，不得包含 `/`、`\`、控制字符、`.` 或 `..` 路径段。不得通过符号链接离开输出根目录。

同一版本必须同时包含：

- `<选题>_口播稿_vNNN.txt`
- `<选题>_创作诊断_vNNN.md`
- `<选题>_B站发布包_vNNN.md`

版本从 `v001` 开始。只要同版本任一目标文件已存在，该版本即视为占用；选择下一空闲版本。任何情况下都不得覆盖、截断或原地更新既有创作包。

## 口播稿 TXT

第一行严格为：

`苏格拉底的猫今天聊的是，<选题>`

第一行后空一行。第二个非空段落必须是增长钩子。全文只保留观众会听见的正文，使用中文标点和自然短段落。

禁止出现：

- Markdown 标题、代码围栏、链接、来源表或加粗符号。
- `第一部分`、`核心观点一`、`镜头`、`BGM`、`停顿`、`预计时长`等内部标签。
- 写作说明、证据注释、舞台动作或模型自评。
- 默认的点赞、关注、收藏、转发要求。

以去除空白和 Unicode 标点后的字符数估时：

- 慢速估计：字符数 ÷ 4.0。
- 快速估计：字符数 ÷ 4.5。
- 用户未指定时，默认目标区间为 180–240 秒（约 3–4 分钟）。
- 内容确有需要时可以超过 240 秒，但延长部分必须承担不可删的研究证据、作用机制、证据边界或反例、可执行方法之一。不得用重复结论、同义改写、装饰性故事或形容词堆砌凑时长；删掉后若不影响结论可信度、理解或行动，就应删除。
- 慢速估计超过 240 秒时，`字数与估时` 必须写明 `延长依据`，具体指出新增内容的信息功能；“内容丰富”“需要讲完整”等空泛说明无效。依据缺失或无效属于校验错误。
- 按 4.0 字/秒计算的慢速估计不得超过 600 秒（10 分钟）。超过硬上限属于校验错误；低于默认目标区间只作校验警告，不得机械增补内容破坏逻辑。

## 创作诊断 MD

必须按以下顺序出现：

1. `# 创作诊断`
2. `## 基本信息`
3. `## 所选方向`
4. `## 钩子依据`
5. `## 结构图`
6. `## 五维诊断`
7. `## 事实—证据—边界`
8. `## 来源`
9. `## 字数与估时`
10. `## 主要修改对照`，仅旧稿改写模式必需

`基本信息`必须写明选题、创作模式、版本；旧稿改写还要写源文件路径和写作前 SHA-256。

`所选方向`必须包含以下字段：

- `国内大众切口`
- `目标人群`：具体到生活阶段、任务或处境，不得只写“中国人”“国内大众”“大家”或“当代年轻人”。
- `现实需求`：这类人正在完成什么任务、作什么判断，或降低什么成本与风险。
- `具体痛点`：阻碍需求实现的可观察问题。
- `可感知槽点`：期待、规则或直觉与实际经历之间的具体落差；不写地域梗或群体嘲讽。
- `正文原句`：逐字摘录口播 TXT 中承载该切口的一段连续原文，不加省略号，不得只在诊断中补写。
- `泛化边界`：说明该场景不能代表哪些人，或相关结论不能外推到什么范围。

若选题没有实质性的国内差异，仍应识别国内观众的具体理解需求与学习摩擦，并在 `泛化边界` 写明无须强行本土化的理由；不得省略这些字段。该内容用于复核选题与中国大陆普通公众的真实关联，不能只堆放“中国、需求、痛点、槽点”等关键词。

若钩子或正文涉及国内现状、规模、趋势、政策、平台规则、公共服务或群体差异，`钩子依据`应说明对应的国内情境，相关主张必须进入 `事实—证据—边界` 表。单一城市、个案、热搜、评论区或平台样本不得外推全国；无法核实的普遍性判断应删除、降格或改写为有条件的具体场景。

`五维诊断`必须逐项覆盖钩子、逻辑、具体性、AI 味、传播力，并使用 `强`、`可用`、`需改`之一。

`事实—证据—边界`使用 Markdown 表格，固定列为：

`主张｜核验结论｜证据边界｜来源`

来源使用直接 Markdown 链接。若某个候选主张无法核实，应说明已从正文删除或降格，不能让空白证据表制造“已核验”假象。

`字数与估时`记录去标点字符数、4.0 字/秒估时、4.5 字/秒估时、目标来自用户指定还是默认区间，以及是否满足 600 秒硬上限。慢速估计超过 240 秒时，还必须另起一行记录 `延长依据：<不可删的信息功能及具体内容>`。

## B站发布包 MD

必须按以下顺序出现：

1. `# B站发布包`
2. `## 标题候选`
3. `## 封面文案`
4. `## 视频简介`
5. `## 标签建议`
6. `## 置顶评论问题`
7. `## 抖音横屏复用文案`
8. `## 视频号复用文案`

固定数量与形式：

- 标题候选恰好 5 条，使用 `1.` 至 `5.` 编号；角度应覆盖好奇、问题、搜索或判断价值，但不得制造虚假承诺。
- 封面文案恰好 3 条，使用 `1.` 至 `3.` 编号；每条去空白后不超过 12 个字符。
- 视频简介一份，说明观众将理解什么，并可自然列出主要公开来源。
- 标签 6–10 个，每行一个 `- 标签`。
- 置顶评论只提出一个有真实回答空间的问题。
- 抖音横屏和视频号各一份复用文案；仅适配措辞，不改动事实结论。

发布包不得声称“必火”“保证播放量”“科学证明所有人”或其他超出证据的承诺。

## 文件写入与验证

解析版本后、写入前，再确认三个目标均不存在。创建文件时只使用新文件操作；若出现竞争或冲突，重新解析下一版本。

完成后运行 `scripts/validate_package.py`。校验器负责结构、数量、固定首行、纯口播限制、路径、版本、UTF-8、符号链接和源稿哈希检查；它不会判断主张是否真的被来源支持，因此创作者仍须人工核对证据映射。
